1Rate limiting with token buckets▾

A token bucket holds an allowance that refills continuously at a fixed rate; each request drains tokens equal to its cost, and is admitted only if enough remain. Unlike a fixed one-minute window, continuous refill has no "reset" moment, so it can't be gamed into a burst near two windows' worth of traffic at the boundary.

Now you're ready: WLM checks two buckets per request — RPM and TPM — and the tricky part is that TPM cost (output tokens) isn't known until generation finishes.
2Multi-writer state and consistent hashing▾

If many machines must update one shared counter, letting all of them write creates a hotspot. Consistent hashing deterministically maps each key (here, a quota) to a small, stable subset of writers — every machine computes the same mapping independently, and the mapping barely changes as the fleet grows.

Now you're ready: WLM uses consistent hashing to pick which few admission-control instances are responsible for each customer's quota — not to place data, but to select writers.
3Prompt / KV caching in LLM serving▾

Transformer inference caches the key-value state for a prompt's prefix so a later request sharing that prefix skips recomputing it — a prompt cache. This cache lives on whatever accelerator served the original request, so it's regional: move the request, lose the cache, and pay to rebuild it.

Now you're ready: this is why WLM treats "which region serves this request" as a caching decision, not just a load-balancing one.
4Exponential moving averages▾

An EMA is a running average that weights recent observations more heavily, smoothing out noise while still tracking a slow trend — unlike a fixed threshold, it moves with the workload's own diurnal shape.

Now you're ready: WLM's classifier compares current token/request rate to an EMA baseline, not to a fixed cap — the same absolute rate can be normal at 2pm and anomalous at 2am.
5AIMD congestion control▾

The classic TCP idea: grow a limit slowly and steadily when things go well (additive increase), but cut it sharply the moment there's a sign of trouble (multiplicative decrease). This asymmetry keeps the system near capacity without regularly overshooting it.

Now you're ready: WLM's scheduler discovers each hosting layer's current sustainable concurrency the same way — no static capacity number needed.
6Fair queueing and priority scheduling▾

Stochastic fair queueing (SFQ) hashes tenants into a fixed number of round-robin queues so no single customer can starve the rest. Deficit round-robin (DRR) extends this across priority classes, giving each a guaranteed dispatch share so lower priority is delayed, not starved.

Now you're ready: WLM layers both — SFQ for per-customer fairness, DRR across five service-tier/classification priority levels.
7Bounded staleness vs. synchronous consistency▾

Consulting a single global authority before every decision guarantees correctness but adds a network round trip to every request. Bounded staleness instead decides from local or cached state and reconciles the true global state on a schedule, accepting a temporary, quantifiable amount of error in exchange for speed.

Now you're ready: this trade-off, plus layered fallbacks ("defense in depth") to contain the temporary error, is WLM's central design choice.
The whole story in one place

WLM in a nutshell

Two principles, five cooperating subsystems, and why coordination stays off the request path.

Bedrock serves millions of inference requests per minute across 30+ regions, but accelerator capacity for any given model sits in only a subset of them, unevenly. A request's true cost isn't known at admission — output length is revealed only as generation streams out. Under these constraints, exact global coordination is too slow: a cross-region round trip alone costs 60–170 ms in production — and synchronous admission checks in a controlled three-region test saw medians up to 211 ms in the farthest region — against a 10 ms admission-control latency budget.

WLM's answer is two principles. First, decouple ingress from execution: a request lands in whichever region is nearest, but CRIS may execute it elsewhere, subject to geography and model placement, with prompt-cache locality as a first-class routing constraint rather than an afterthought. Second, favor bounded inconsistency over synchronous coordination: admission control decides from locally cached quota state, reconciling consumption every 2–5 seconds through a globally replicated store; routing weights refresh off the request path from asynchronously collected capacity signals.

Five subsystems implement this: admission control, traffic classification, cross-region routing (CRIS), request scheduling, and an orchestrator that sequences them, propagates metadata, and — when any subsystem is unavailable — fails open, substituting the best local decision rather than failing inference.

🍯 Key takeaways

  • Local, cached decisions beat synchronous global ones when cross-region RTT (60–170 ms) — and synchronous admission latency of up to 211 ms in the farthest region — dwarf the latency budget (10 ms).
  • Bounded staleness means quantifiable, bounded temporary error — not unbounded drift.
  • Overshoot during divergence is capped at N× the quota, where N is the small, stable set of responsible instances (consistent hashing keeps N small).
  • Traffic classification labels rate of change, not absolute volume — it protects against sudden shifts, not steady-state demand (that's admission control's job).
  • CRIS orders decisions strictly: availability > prompt-cache locality > latency/utilization — no blended score.
  • Fail-open everywhere: a failed subsystem drops its own protection, not inference availability.
  • Under WLM's sustained-overload tests, both designs' final-phase admitted load stayed within 1.1% of quota — not a proof of equivalence under all workloads or failures.
Six everyday pictures

How to think about WLM

Each stands alone. Every card names where the picture stops holding.

Admission · bounded staleness

Neighborhood ATMs, one bank ledger

Each ATM lets you withdraw from a local cash reserve instantly; the bank reconciles the shared ledger overnight. Occasionally two ATMs both let you overdraw before the ledger catches up — bounded by how many ATMs exist, not unlimited.

Where it breaks: a real bank eventually calls a debt collector; WLM just throttles future requests until the negative balance is repaid through refill.
Classification · EMA baseline

A rolling forecast, not an almanac

A weather forecaster compares today to the recent rolling trend, not to a fixed historical average — a hot day in August isn't "anomalous" the way the same temperature in January would be. WLM's classifier compares current rate to each customer's own recent EMA, so the same request volume can be normal or anomalous depending on when it arrives.

Where it breaks: a forecaster has years of data; a new ingress region has none, so WLM defaults new traffic to "anomalous" until a baseline forms.
CRIS · damped weight changes

GPS that only reroutes when it's worth it

A good GPS won't reroute you off a familiar highway to save thirty seconds — the value of staying on a known road (no missed exit, no confusion) outweighs a marginal gain. CRIS moves routing weights gradually and skips updates when the benefit doesn't justify abandoning warm prompt caches.

Where it breaks: GPS reroutes for you personally; CRIS's routing weight is a shared setting for a whole key-space, so a change affects many customers' cache locality at once.
Scheduling · shard leader lease

A relay baton, not a handoff

A relay runner who goes silent doesn't hand off the baton — the next runner simply starts once the silence has lasted long enough to be sure. A shard leader renews its lease every 200 ms; after five missed renewals (1 s), another instance takes over and rebuilds the queue from callers still waiting.

Where it breaks: the new "runner" doesn't know the full queue instantly — membership is only complete once every waiting caller has re-polled, about a second later.
Scheduling · DRR priority

Priority boarding, not a locked gate

Priority boarding lets first class through first, but economy still boards — just later. DRR gives every priority tier a guaranteed dispatch share, so Batch and anomalous traffic wait behind Provisioned Throughput and standard On-Demand rather than being rejected outright.

Where it breaks: a flight has one boarding order; WLM can also preempt — bump an already-running low-priority Batch request off the accelerator, which no airline does to a seated passenger.
Concurrency · AIMD

Cruise control that nudges, then brakes

Adaptive cruise control eases the throttle up gradually when the road is clear, but brakes hard the moment the car ahead slows. WLM's concurrency limit grows a small percentage per accepted request but drops multiplicatively the instant the hosting layer throttles or latency rises.

Where it breaks: cruise control reacts to one sensor; WLM's loop only probes upward when there's already enough traffic and completed requests to trust the signal.
The full explanation

How it actually works

Subsystem by subsystem, with the paper's formulas and real parameters.

1 · Request flow

A request is authenticated at ingress, then passes through four cooperating subsystems in dependency order, spanned by an orchestrator that propagates context and applies fallbacks.

2 · Admission control & distributed quota

Every request checks two continuously-refilled token buckets — RPM and TPM — keyed by (customer, model, scope, tier). The TPM deduction is an estimate; streaming requests report cumulative usage and a final reconciliation repays or collects the difference.

To let many instances collectively enforce one quota without a storage hotspot, each quota is assigned — via consistent hashing — to a small, stable subset of N admission-control instances. Only they read/write that quota's shared record, via optimistic concurrency control against DynamoDB, every 2–5 s with jitter.

# fast path — every request, target p99 < 10 ms
if RPM_bucket.has_capacity() and TPM_bucket.has_capacity(estimate):
    deduct(estimate); admit()
else:
    reject()

# background path — every 2-5s, per responsible instance
read latest replicated consumption
merge local observed usage + refills
write back with optimistic concurrency
refresh local cache
💡
Why the overshoot is bounded by N, not the fleet: before reconciliation, each of the N responsible instances can independently admit up to its own view of the bucket. Worst case, admitted rate reaches N× the quota — subsetting is what keeps N small instead of equal to the whole fleet.

3 · Traffic classification

Two independent EMA-based classifiers — token rate and request rate — each compare current demand to the customer's own recent baseline (α = 0.01 per active minute). A request is anomalous if either exceeds its threshold (token: 2.0×, request: 1.5×), combined with logical OR because missing a real burst is costlier than one false positive.

📈
The EMA window is tuned to roughly the time the hosting layer needs to add capacity — so classification catches demand changing faster than capacity can follow, not demand that's merely large. A gradual ramp may never be flagged, by design.

4 · Cross-Region Intelligent Spillover (CRIS)

For region r, headroom below a target utilization is:

H_r = max(0, C_r · U_target − L_r)   # C_r = capacity, L_r = observed load

Global (movable) traffic is distributed toward headroom, steered away from pressured regions; geographically constrained traffic is distributed within its scope by capacity alone, since it has no alternative. Priority is fixed, not blended: availability > prompt-cache locality > latency/utilization.

Weights are computed off the request path every 5 minutes per ingress region, then served from a local cache. For cache-sensitive requests, a sticky key derived from the prompt prefix is mapped via weighted consistent hashing, so related requests keep landing in the same region while weights still control the overall split. When a region must exit the eligible set, normalization is direction-constrained — residual weight only flows toward regions whose target was already increasing — so a region whose target fell can't be pushed back up by the rebalancing math.

5 · Scheduling: fairness, priority, concurrency, shedding

At the destination, SFQ hashes customers into fixed queues for fairness; DRR gives five priority levels (pr10 Provisioned Throughput → pr150 Batch, with anomalous On-Demand between standard On-Demand and Flex) a guaranteed dispatch share, so lower tiers wait rather than starve. Higher-priority arrivals can preempt a running Batch request.

Concurrency limits adapt via AIMD:

C(t+1) = C(t) + ceil(α · C(t))   # accepted → grow ~2.7%/step, α=0.0266
C(t+1) = C(t) · β              # throttled/slow → cut, β∈[0.85,0.95] by severity

When queues exceed depth despite this, the scheduler sheds anomalous before standard, and opportunistic tiers before either — after a delay, in case pressure is transient.

Follow the numbers

Worked examples

Four traces using the paper's real parameters and measurements.

① The N× overshoot bound (Table 2)

Two-region topology, N = 6 responsible instances; a 1-second burst finishes before reconciliation can propagate. What's admitted?

  1. Worst case: each of the 6 instances can independently admit up to one full bucket before learning what the others admitted → ceiling = 6 buckets.
  2. Measured at the ceiling: offering 6 buckets in 1 s yields 5.92 admitted (98.7% of the ceiling) — nearly every independent instance used its full local allowance.
  3. Below the ceiling: offering 3 buckets yields exactly 3.00 admitted — bounded staleness tracks real demand when demand is under the bound.
  4. Synchronous baseline, same burst: stays near 1.01–1.02 buckets — every request consults the same authority, so there's nothing to diverge.
  5. Cost of the overshoot: excess becomes a negative balance; for a one-minute bucket, repaying a worst-case N× burst takes up to (N − 1) minutes of throttled refill — it borrows against future allowance, not long-run quota.
🍯
Insight: subsetting to N instances (via consistent hashing) is what turns "unbounded overshoot" into "N× for one window" — the whole design hinges on N staying small.

② CRIS headroom in a healthy vs. saturated region

U_target = 0.8. Region X: capacity 1,000, load 650. Region Y: capacity 500, load 480. How much global traffic does each draw?

  1. Region X: H = max(0, 1000×0.8 − 650) = max(0, 800 − 650) = 150 headroom units — draws global spillover.
  2. Region Y: H = max(0, 500×0.8 − 480) = max(0, 400 − 480) = max(0, −80) = 0 — the clamp means an already-pressured region draws zero global traffic.
  3. Geographically constrained traffic bound for Region Y still lands there regardless — it has nowhere else to go, which is exactly why CRIS computes its distribution separately from global traffic.
💡
The max(0, ·) clamp is doing real work: it's the difference between "send less" and "send none," and it's what protects narrow-scope traffic from being crowded out by movable traffic chasing the last bit of headroom.

③ AIMD concurrency: five good steps, one bad one

Start C₀ = 1000, α = 0.0266, then a throttle event with β = 0.9.

  1. Step 1: C₁ = 1000 + ⌈0.0266×1000⌉ = 1000 + 27 = 1027.
  2. Step 2: C₂ = 1027 + ⌈0.0266×1027⌉ = 1027 + 28 = 1055.
  3. After 5 accepted steps: C₅ ≈ 1150 — roughly +15% over five accepted decisions, additive and steady.
  4. Throttle hits: C₆ = 1150 × 0.9 = 1035 — one bad signal erases most of that growth in a single step.
  5. Why asymmetric: overshoot costs queueing, rejection, and lost cache hits; undershoot only costs temporary idle capacity — the loop is built to prefer the cheaper mistake.

④ Prompt-cache locality: what routing preserves

Public-benchmark numbers from a full-day run with 2,048+ token prefixes.

  1. Reuse rate: 99.78% of repeats hit a warm cache — an upper bound on routing-induced locality loss (0.222% failed, possibly from eviction, not just movement).
  2. Prefix-dependent latency: falls 45%, from 33.9 to 18.5 ms per thousand prefix tokens, when the cache is warm.
  3. Median client-observed TTFT: 1,583 ms → 1,413 ms, a 10.7% cut, from that same warm-cache effect.
  4. p99 TTFT: 8,687 ms → 3,397 ms, a 61% cut — the tail benefits far more than the median, consistent with cache misses being the source of the worst outcomes.
🍯
Insight: this is the concrete cost CRIS is protecting against every time it chooses to keep a request in a warmer, farther region over a cooler, closer one.
Test yourself

Practice problems

Try each before opening the answer.

Problem 1 · easy
Why doesn't WLM just query a single global quota authority for every request?
Show answer
Cross-region RTT runs 60–170 ms in production, while the admission-control latency budget is 10 ms — even typical neighboring-region RTTs (~10 ms) are comparable to the whole budget, and cross-continent RTTs exceed it by an order of magnitude or more.Misconception: that correctness requires synchronous consultation. In WLM's sustained-overload tests, local decisions plus background reconciliation kept final-phase admitted load within 1.1% of quota — not a general proof of equivalence under all workloads or failures.
Problem 2 · medium
A quota has N = 9 responsible instances across three regions. What's the theoretical worst-case admitted volume for a 1-second burst that completes before reconciliation, in units of one bucket?
Show answer
Up to 9 buckets — each of the 9 instances can independently admit close to a full bucket before any of them learns what the others did. The measured value was 8.65 of 9, close to the theoretical ceiling.Misconception: that more instances always mean more inconsistency risk without bound. It's bounded exactly by N, which is why consistent hashing keeps N small and configurable per quota.
Problem 3 · medium
Why does traffic classification use an EMA baseline instead of a fixed request-rate cap?
Show answer
A fixed cap can't distinguish a customer's normal peak-hour traffic from a genuine sudden change — it would either flag routine diurnal peaks or miss real bursts at off-peak baselines. An EMA tracks each customer's own recent trend, so the same absolute rate is judged against what's normal for that customer, right now.Misconception: that classification limits how much traffic a customer can send. It only affects scheduling priority under contention — absolute volume is admission control's job.
Problem 4 · hard
CRIS's priority order is fixed (availability > cache locality > latency/utilization) rather than a single blended score. What does fixing the order buy, and what does it cost?
Show answer
It makes conflicts resolvable without case-by-case tuning: CRIS generally prefers to accept higher latency to preserve a warm cache — subject to eligibility, the destination's queue-delay tolerance, declines, and terminal queue bounds — and abandons that cache once availability is at stake — no weighting coefficients to retune as traffic shifts. The cost is inflexibility: a blended score could in principle find a better tradeoff point for some workload, but fixed order avoids the fragility of getting those weights wrong at global scale.Misconception: that a smarter, unified score would strictly dominate. Fixed priority trades some theoretical optimality for predictable, debuggable behavior under conflicting signals.
Problem 5 · medium
A shard leader's lease is 1 second, renewed every 200 ms, and failover triggers after 5 missed renewals. Why not fail over after just 1 missed renewal?
Show answer
Failing over too eagerly risks displacing a leader that's still alive but briefly delayed (e.g., a GC pause or transient network blip), which pauses dispatch and can trigger repeated leadership churn. Waiting for 5 missed renewals trades a bit of extra stall-on-failure time for much better stability against false positives.Misconception: that faster failover is always better. There's a real tradeoff between mean-time-to-recovery and churn from false failovers.
Problem 6 · hard
When the replicated quota store becomes unavailable, admission control keeps deciding from local state rather than rejecting requests. What exactly stops being true during that time, and what still bounds the damage?
Show answer
Cross-instance agreement on quota consumption stops being true — each responsible instance enforces only its own local view, so the effective ceiling rises to N× the configured limit instead of the true limit. What bounds the damage: N is still small and fixed by consistent hashing, per-customer fairness and adaptive concurrency at the scheduler still cap how much of that excess actually reaches execution, and once the store returns, buffered updates reconcile and convergence resumes automatically.Misconception: that "fails open" means no protection at all. It means one layer's protection weakens while other layers (fairness, shedding, circuit breakers) keep operating.
Problem 7 · easy
Why does a new ingress region default an unfamiliar customer's traffic to "anomalous" instead of "standard"?
Show answer
Classification baselines are regional and not replicated, so a new ingress region has no history for that customer. Defaulting to anomalous is the conservative choice because a false negative during cold start could expose other customers to an unobserved spike, while a false positive only lowers priority during contention — it never rejects the request outright.Misconception: that "anomalous" means blocked or throttled. It only affects scheduling priority when the destination region is contended.
Quick answers

Frequently asked questions

Q1What does "bounded inconsistency" actually guarantee?▾
Temporary divergence between independent instances' views of shared state, confined to a known window (the reconciliation interval, or N× the quota for admission), followed by deterministic convergence once background reconciliation runs. It is not unlimited drift.
Q2Why is admission decoupled from routing instead of one combined decision?▾
They fail independently and serve different purposes: admission enforces a customer's budget, classification labels demand changes, and CRIS picks where to run. Combining them into one call would save a hop but couple their failure modes — if one part of a merged call failed, both protections would be lost together.
Q3Why can't fixed-window rate limiting replace token buckets here?▾
Fixed windows allow bursts up to nearly 2× the intended rate across an adjacent window boundary. Continuous refill has no boundary to exploit.
Q4Does classification ever reject a request?▾
No. The label (standard/anomalous) only affects scheduling priority, and only when the destination region is actually contended. A misclassified request is delayed, never dropped, by this subsystem.
Q5Why does CRIS compute separate distributions for geographically constrained vs. global traffic?▾
Because their alternatives are asymmetric — global traffic can move elsewhere under pressure, constrained traffic cannot. A single utilization-based split would let movable traffic crowd out capacity that constrained traffic has no alternative for.
Q6What happens when a declined dispatch attempt occurs at the destination?▾
The router tries the next candidate region, paying one additional cross-region round trip and possibly losing prompt-cache locality — the visible cost of routing on stale or inaccurate weights.
Q7Why does adaptive concurrency grow additively but shrink multiplicatively?▾
Overshoot causes queueing, rejection, retries, and lost cache hits — expensive. Undershoot only idles accelerators temporarily until the next increase — cheap. The asymmetry biases the loop toward the cheaper mistake.
Q8Is Batch traffic ever guaranteed capacity?▾
No — it's opportunistic, using capacity that would otherwise be idle, and can be preempted the moment higher-priority demand needs it. Before WLM's work-conserving preemption, Batch was capped at ~15% of hosting capacity; after, it used 70–100% of otherwise-idle capacity.
Q9What's the actual failure mode if admission control itself is entirely unreachable?▾
Requests are admitted rather than failed, and nothing enforces the quota limit until admission control returns — this is the one case where the N× bound doesn't apply, because it depends on admission control still running at all.
Q10Why keep prompt-cache locality as a routing concern rather than a hosting-layer concern?▾
Because the decision of where to route a request determines whether its cache is reusable at all — hosting can only serve what's already local. Making it a first-class routing constraint (not an afterthought) is what lets CRIS trade a little latency for avoiding expensive prefix recomputation.

This guide's framing (not paper claims): the "bounded staleness resembles relaxed consistency" connection below, and all analogies, are this guide's interpretation for a systems audience, not statements from the paper.

A note for readers of OS memory-tiering work

WLM's core trade — decide from local/cached state, reconcile asynchronously, bound the error with a small enforcing subset — parallels patterns in tiered-memory systems: NUMA/CXL-pooled memory access often accepts relaxed consistency for latency, and hot/cold page migration (as in TPP- or HeMem-style tiering) makes movement decisions balancing locality benefit against migration cost, much as CRIS weighs prompt-cache locality against routing benefit. The quota-reconciliation-as-negative-balance mechanism is also structurally similar to credit-based flow control used in some CXL.mem link-layer designs. These are this guide's connections, not claims made by the paper.
