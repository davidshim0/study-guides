Recovering whose stall is whose

Two workloads share one cache and one memory system. Every hardware counter blends their requests together, so a tiering policy can't tell whose miss is expensive and whose isn't. This is the plain-English story of Tierce, the observability substrate that untangles them.

📄 Xu, Inceisci, Li, Zhang, Li — "Tierce" (SOSP 2026) 🎓 CXL/tiering fundamentals assumed — jumps straight to the aliasing problem ⏱ ~25 min read
👁️

Measure each workload's OWN exposed stall — never the SHARED blur left once cache and memory mix everyone's requests together.

Before you begin

Eight ideas the paper assumes you know

Collapsed by default — open whatever's unfamiliar, skip the rest.

foreground (FG) workload background (BG) co-runner Tierce's machinery aliasing / the PACT baseline
1PEBS and LDLAT — sampling, not counting▾

PEBS fires a hardware record on a sampled event (e.g. every P-th LLC miss) tagged with the instruction and data address, so software can attribute it to a page. LDLAT is a variant that additionally reports the load's realized latency and which level of the hierarchy served it (L2, L3, local DRAM, remote/CXL).

Now you're ready: Tierce reuses PEBS for ownership (which page) and LDLAT for latency (§4.4) — two different views of the same sampled access.
2CHA, TOR, and the uncore path▾

Past the LLC, a miss enters the "uncore." On Intel chips the Caching/Home Agent (CHA) routes it to local DRAM or CXL and tracks it in a Table Of Requests (TOR) until it completes. TOR counters expose occupancy (outstanding requests) and active cycles — the raw material for MLP.

Now you're ready: CHA/TOR counters are normally aggregate across every core. Tierce's whole MLP fix (§4.3) is about filtering this stage per core.
3Cache Allocation Technology (CAT)▾

CAT lets software restrict which LLC ways a core (or group of cores) may allocate into, via the resctrl interface. It doesn't move data — it just changes who gets to keep a line when the set is full.

Now you're ready: Tierce uses CAT to control the miss stream upstream of the tiering policy, not to manage capacity directly (§4.5).
4Hotness vs. criticality▾

Early tiering systems ranked pages by access frequency ("hotness"). Newer ones rank by estimated CPU stall saved by promotion ("criticality") — a page accessed rarely but always on the critical path can matter more than one accessed constantly but overlapped with other work.

Now you're ready: PACT formalized criticality as PAC; Tierce keeps PAC as the objective and fixes how it's measured under colocation.
5PACT and Page Access Criticality (PAC)▾

PACT (the direct predecessor this paper builds on) samples LLC-miss accesses with PEBS, estimates per-tier MLP from aggregate counters, and scores each sampled page by its access count discounted by that MLP. Pages above the 75th percentile (Q3) become promotion candidates; everything — the score distribution, threshold, queue, and fast-tier budget — is global across every workload on the box.

Now you're ready: that global sharing is exactly what breaks under colocation — it's Table 1 in the paper, and the spine of the "How It Works" tab.
6Time aliasing vs. space aliasing▾

Two distinct ways colocation corrupts a signal. Space aliasing happens before a request reaches memory: shared-LLC interference changes whether an access becomes a memory request at all. Time aliasing happens after: once at the memory controller, workloads experience different queuing delay and MLP, but aggregate counters merge them.

Now you're ready: this is the paper's central conceptual split — Tierce has one mechanism for each (CAT for space, wMLP/LDLAT for time).
7Domain isolation and cgroups▾

An execution domain here means a disjoint set of cores plus a memory cgroup: one FG or BG workload's cores, memory budget, and (in Tierce) its own tiering state, none of it shared with a neighbor.

Now you're ready: "domain-isolated" throughout this guide just means: separate histogram, separate queue, separate fast-tier budget, per workload.
8Where this sits among tiering systems you already know▾

TPP and HeMem place pages by hotness/access frequency, largely for one workload's own isolated memory. Memtis adds dynamic page-size and classification but still scores globally. Pond and CXL memory-pooling work decide where capacity comes from, not which pages deserve it. Colloid argues access latency is the right criterion, close to PACT/Tierce's premise, but neither isolates per-workload measurement under colocation.

Now you're ready: Tierce's contribution is orthogonal to most of these — it's an observability layer that any criticality-based policy (PACT's PAC, in this case) needs once you stop assuming a single tenant.
The whole story in one place

Tierce in a nutshell

The observability gap, the fix, and why it's a composition rather than a new algorithm.

Production tiered-memory systems place pages using hardware-observed criticality — PACT's PAC score discounts a page's LLC-miss cost by how much latency was hidden by memory-level parallelism (MLP). That works when one workload owns the machine. Colocate a foreground (FG) workload with a best-effort background (BG) co-runner and two things break the estimate: space aliasing (shared-LLC interference changes which accesses even become memory requests) and time aliasing (shared queuing and MLP change what those requests cost once they arrive). Aggregate hardware counters blend both effects across workloads — PAC computed from them describes neither workload accurately.

Characterizing 138 colocated executions, the authors find the single most consistent predictor of slowdown is the colocation-induced change in L2-miss latency (ΔL2Lat, r=0.91 across all apps on CXL, 0.96 excluding client-server workloads) — but it requires an interference-free solo baseline no production system has, and gives no page-level attribution. Tierce is the substrate that recovers page-level, workload-scoped signals anyway: per-domain PAC histograms/queues/budgets, workload-specific MLP (wMLP) from TID-filtered CHA/TOR counters, latency-selective admission (LDLAT, 350-cycle floor) that weights each sample by its realized cost, and bounded LLC residency via CAT so the miss stream Tierce scores is itself not corrupted by the co-runner.

The payoff: across 8 colocated pairs (4 FGs × 2 BGs) on Skylake, Tierce beats PACT on every pair, by 2.2% to 12.6%. Its worst case is 0.5% above the untiered baseline and 7.4% below that pair's colocated all-DRAM reference. Its largest margins over NUMA-balancing tiering (NBT), Colloid, and Memtis are 22.7%, 25.9%, and 64% respectively.

🍯 Key takeaways

  • Colocation aliases page-criticality signals in two independent places: the shared LLC (space) and shared memory queuing/MLP (time).
  • ΔL2Lat is the best offline predictor of slowdown but can't drive online policy — no solo baseline, no page attribution.
  • wMLP restores per-workload overlap from TID-filtered, per-tier CHA/TOR counters, not aggregate ones.
  • LDLAT admits only samples above a realized-latency threshold (350 cyc, adaptive to 700 cyc under fast-tier pressure), concentrating a smaller promotion budget on genuinely expensive accesses.
  • CAT bounds LLC interference before the miss stream reaches the tiering policy — an affine model predicts a colocated pair's way-sensitivity curve from just two calibration points.
  • Every stage — histogram, admission threshold, migration queue, fast-tier budget — is kept per domain, so one workload's volume can't starve another's.
  • Result: beats PACT on all 8 pairs (2.2–12.6%), and beats NBT/Colloid/Memtis by up to 22.7%/25.9%/64%.
Six everyday pictures

How to think about Tierce

Each stands alone. Every card ends with an honest note on where the picture stops being true.

Domain isolation

One shared tip jar, two baristas

A high-volume espresso line and a slow specialty-drink counter share one tip jar. Whoever asks for tips more often (higher sample volume) ends up dominating the split — even if the specialty barista's customers genuinely value her work more. Give each their own jar and the split reflects merit, not traffic. That's why a shared promotion queue let one BG workload consume up to 95% of all promotions in the authors' measurements.

Where it breaks: real tip jars don't have a hard capacity ceiling the way a memcg fast-tier budget does — Tierce's isolation also caps how much each barista can keep, which the jar metaphor doesn't capture.
wMLP

One stopwatch for two swimmers

A fast swimmer's overlapping strokes and a slower swimmer's get timed with one shared stopwatch, so both look mediocre in the average. Give each their own timer and the fast one's real overlap shows up. Aggregate per-tier MLP does the same averaging to memory requests: a low-MLP workload's true stall gets compressed toward the co-runner's overlap. wMLP is that second stopwatch, computed per core from TID-filtered CHA/TOR occupancy.

Where it breaks: swimmers don't share a lane the way concurrent memory requests share the same physical queue — the "aliasing" here is a real resource-sharing effect, not just a measurement artifact you could fix by timing more carefully.
LDLAT admission

Escalating only the slow calls

A support line logs every call, but only escalates the ones that waited past a fixed threshold — most short calls resolved fine and don't need a manager's attention. LDLAT does the same to sampled loads: it only admits ones whose realized latency clears 350 cycles (raised to 700 under fast-tier pressure), so a small promotion budget goes to pages that are actually paying slow-tier cost, not ones that merely got accessed.

Where it breaks: a support call's "badness" is judged after the fact by a human; LDLAT's threshold is a fixed hardware/software cutoff applied identically to every access, with no case-by-case judgment — it's closer to a spam filter than a triage nurse.
Space vs. time aliasing

Two different blurs on one photo

One blur comes from camera shake before the shutter closes (space aliasing — the LLC's eviction pattern shifts before a request even leaves the chip); another comes from a slow exposure after the shutter's already open (time aliasing — queuing and MLP shift after the request reaches the memory controller). Fixing one doesn't fix the other, which is why Tierce needs two separate mechanisms (CAT vs. wMLP/LDLAT), not one.

Where it breaks: a photo's two blurs are both distortions of the same static scene; the LLC and memory-controller effects are distortions of genuinely different, concurrently-changing resource contention — there's no single "clean exposure" hiding underneath both.
Bounded LLC residency

Reserved lanes on a shared highway

A carpool lane guarantees the protected commuter a minimum share of the road regardless of how much everyone else wants to merge in. CAT does the same for cache ways: the FG's domain always keeps at least its floor (5 of 20 ways on EMR), so a bandwidth-hungry co-runner can't evict its way to dominance before the tiering policy even samples a miss.

Where it breaks: CAT allocates a fixed number of ways uniformly across every cache set — a highway lane can vary in width by segment, but there's no equivalent local flexibility here.
Affine prediction

Two thermometer readings, one forecast

Measure a location's temperature at 6am and 2pm under clouds, compare it to the known clear-day curve, and you can rescale the whole clear-day forecast to predict the cloudy one — without re-measuring every hour. Tierce does this for LLC way-sensitivity: fit an affine transform (g(x)=a·f(x)+b) to a workload's solo curve at just two colocated allocations, and it predicts the rest of the colocated curve within 0.9 points.

Where it breaks: temperature curves are smooth by physics; some FG/BG pairs have colocated sensitivity curves that don't rescale affinely from the solo one — the paper's own worst-case fit error is 19%.
The full explanation

How it actually works

Section by section, with the paper's tables and formulas rebuilt as visuals.

1 · What each mechanism actually observes

No single hardware facility exposes everything PAC needs. The paper's Table 2 makes this explicit — ownership (which workload/page issued an access), residency (LLC hit or which memory tier), overlap (how much latency MLP hid), and latency (realized time). Each mechanism covers a different subset:

2 · Domain-isolated placement

Each execution domain (an FG or BG's cores + memcg) maintains its own PAC histogram, admission threshold, migration queue, and fast-tier capacity. A migration worker visits domain queues round-robin, and kdemotiond — one instance per cgroup–node pair, mirroring per-node kswapd — reclaims a cold page from a domain's own LRU before admitting a promotion into a full domain. Promotion, demotion, and capacity enforcement never cross a domain boundary.

💡
Why raise admission from Q3 to the 90th percentile? Splitting the pipeline per domain already stops one workload from crowding another's candidate set; the tighter percentile then concentrates each domain's own budget on fewer, higher-scoring pages instead of promoting everything above the 75th percentile — PACT's own Q3 cut.

3 · Workload-specific MLP (wMLP)

Intel CHAs expose a Thread/Core-ID filter, but the encoding isn't mapped to Linux CPU IDs. Tierce calibrates it once: pin an LLC-miss generator to one logical CPU, sweep the TID range across CHA slices, and record which encoding's TOR activity matches. Repeated per core, this turns an undocumented hardware knob into an OS-usable per-core, per-tier filter.

# per core c, every 20 ms epoch
MLP_c = ΔTOR_OCC_c / ΔTOR_CYC_c        # outstanding slow-tier reqs / active cycles
# domain w spanning cores C_w
wMLP_w = mean(MLP_c for c in C_w)
S_w = k · LLC-misses_w / (wMLP_w · N_w · P)   # base per-sample stall

Because the hardware can't monitor every core–tier pair at once, Tierce time-multiplexes selected pairs across 20 ms epochs, recomputing every input each epoch to track phase changes. Averaging MLP_c across a domain's cores avoids needing to record which thread touched which page.

4 · Latency-selective admission (LDLAT)

PEBS LDLAT tags a sampled load with its realized latency ℓ. The event only fires past a hardware threshold T; at T=32 cycles, cache-labeled samples represent the delayed tail of their class rather than typical hit latency, while remote-memory accesses separate cleanly around 400 cycles (Fig. 5). Tierce sets the hardware floor to T=350 cycles, then filters by data source to drop any remaining cache/local-memory records.

S_p = S_w · (ℓ_p / k_slow)   # per-access weight; k_slow = EWMA(ℓ), β=0.3

A self-tuning controller (LDLAT-Dyn) watches per-domain eviction pressure E_w every second; if the max across domains exceeds τE=0.002 for 30 s, it raises the software gate to 700 cycles, and an emergency check re-applies it within 1 s if pressure spikes past τem=0.015 — so an overly permissive threshold lasts only seconds.

5 · Bounded LLC residency control (CAT)

A page evicted by a co-runner's LLC traffic is gone before either wMLP or LDLAT ever observes it — so Tierce bounds the LLC before scoring. Static sCAT uses an affine model fit at two calibration allocations to predict a colocated pair's whole way-sensitivity curve and picks the minimal protective allocation (fewest ways keeping predicted slowdown within ε=1% of unpartitioned). Dynamic dCAT then adapts within [Wmin, Wmax]=[5,15] of EMR's 20 ways every I=100 ms, using FG MPKI as the release signal:

every 100 ms:
    if FG_MPKI > 25:  W ← W_max          # restore in one step — a miss hurts now
    elif FG_MPKI < 10: W ← max(W-1, W_min)  # release one way at a time
    else: W unchanged
    apply CAT(W, 20-W)
🌱
The response is deliberately asymmetric: an erroneous release costs the FG immediately, while an unneeded retained way only costs the BG some throughput — so the controller leans toward protection.

6 · Enforcement in the kernel

Tierce replaces Linux's deferred residency accounting with synchronous per-cgroup, per-node accounting, draining per-CPU page staging vectors before every kdemotiond scan. That makes the fast-tier budget authoritative regardless of whether a page arrives via move_pages(), NUMA balancing, or another kernel migration path — so admission accounting and demotion always agree on which pages are actually resident.

Follow the numbers

Worked examples

Four traces through the paper's own measurements — PAC rescaling, promotion efficiency, LLC prediction, and tail latency.

① Why wMLP rescales PAC (§5.3)

On sssp-kron, disabling migration but computing PAC from aggregate vs. workload-specific MLP, with identical rankings (same accesses, same order) — only the scale changes. Aggregate per-tier MLP measures 1.31; wMLP measures 1.01. Median PAC shifts from 1078 (aggregate) to 1543 (wMLP), over 17.2M FG samples.

  1. PAC is inversely proportional to MLP in the base-stall formula: S_w = k · misses / (MLP_w · N_w · P). Lower MLP ⇒ higher score for the same misses.
  2. If PAC scaled purely by that ratio: 1078 × (1.31 / 1.01) = 1078 × 1.297 ≈ 1398.
  3. The measured shift is larger — 1078 → 1543, a ratio of 1.431, not 1.297.
  4. The paper doesn't decompose this residual gap. It reports identical rankings with a different PAC scale, and separately notes that PACT's shared admission threshold still lowers the FG's effective priority even as its raw PAC values rise — a qualitative caveat about admission, not an accounting for the extra 1.431/1.297 beyond the MLP ratio.
💡
Insight: wMLP re-centers a workload's PAC scale; the paper separately argues domain-isolated admission (§4.2) is still needed, since a shared threshold can undercut even a correctly-rescaled priority — though it doesn't tie that argument to this specific PAC-shift number.

② LDLAT gets similar retention with 4× fewer promotions (Table 5)

Solo EMR microbenchmark, sweeping wMLP's PEBS sampling period against wMLP+LDLAT (period 5, T=350).

  1. wMLP at period 100: 2.21M promotions, chase rate 6.02 Mops, B-hot residency at 600s = 0.92.
  2. wMLP+LDLAT: 558K promotions, rate 6.24 Mops, B-hot residency = 0.87 — nearly matching quality at 2.21M / 558K ≈ 3.96× fewer promotions.
  3. The volume-alone hypothesis fails: wMLP at period 500 uses almost the same budget (556K promotions) but only reaches 0.59 B-hot residency and a lower post-swap rate (5.83 Mops) — proof that which pages are promoted matters, not just how many.
🍯
Insight: LDLAT's threshold selects a smaller but qualitatively better promotion set — matching wMLP's retention with a quarter of its promotion traffic.

③ Predicting a colocated LLC-sensitivity curve (§4.5, Fig. 7)

For Silo vs. bc-urand, the fitted affine model is g(x) = 1.13·f(x) + 15.23, where f(x) is the FG's solo FG-gain-over-NoCAT curve at x ways.

  1. Two calibration points are measured directly on the colocated pair (the circled points in Fig. 7) to fit a and b — here a=1.13, b=15.23.
  2. Every other allocation is then predicted, not measured: if solo f(x)=−10% at some x, predicted colocated gain = 1.13×(−10) + 15.23 ≈ +3.9%.
  3. Across all 106 sweeps (53 pairs × 2 placements), this two-point fit predicts held-out allocations within 2.0% mean absolute error (worst case 19%).
  4. It even predicts the minimal protective allocation correctly — the fewest ways keeping predicted slowdown within 1% of unpartitioned — in 91 of 106 cases; 12 of the 15 misses over-protect (safe), only 3 under-protect.
💡
Insight: an operator can size a static CAT split from two quick measurements instead of an exhaustive per-pair sweep — directly relevant if you're calibrating CAT-based tiering deployments on new hardware.

④ Tail latency under load: what CAT buys beyond LDLAT (§5.4, Redis)

Redis (19.8 GB RSS) under open-loop YCSB at 90k ops/s, colocated with bc-kron — a load every sampling-based config can nominally sustain.

  1. NoTier queues to 765 ms p99 — well past its knee.
  2. PACT serves the rate but at 339 ms p99 — 434× the all-DRAM reference's 230 μs.
  3. wMLP improves to 3.1 ms; wMLP+LDLAT to 46 ms — better ranking and fewer promotions still leave real queueing delay.
  4. Adding the way partition (Tierce) drops p99 to 422 μs — within ~1.8× of the 230 μs all-DRAM reference, a further ~109× reduction from wMLP+LDLAT's 46 ms.
🍯
Insight: at the tail, closing the space-aliasing gap (CAT) matters far more than further ranking refinement — once queueing dominates, an evicted hot page costs more than a slightly-mis-scored one.
Test yourself

Practice problems

Try each before opening the answer. Every one names the misconception it checks.

Problem 1 · easy
Two accesses land on identical pages A and B with the same frequency, but B's accesses happen to complete slower under colocation. Aggregate hotness-based tiering and PAC-based tiering both see the same access counts. Which one still tells A and B apart, and how?
Show answer
Only Tierce's LDLAT-weighted PAC. Hotness counts accesses, not their cost, so A and B look identical to a frequency-based policy. Vanilla PAC also can't fully separate them at equal frequency — it discounts by MLP-hidden stall using a fixed slow-tier cost, not each access's own realized latency. Only Tierce's LDLAT extension weights each sample by its own realized latency, so B's slower, more expensive accesses score higher.Misconception: that "more accesses" and "more expensive accesses" are the same signal — and that vanilla PAC already fixes this. It doesn't; Tierce's LDLAT extension (§4.4) is what adds realized-latency weighting.
Problem 2 · medium
A shared promotion queue lets a bandwidth-heavy BG workload take 95% of promotions even though the FG's pages are individually more critical. Why does per-domain admission (not just per-domain scoring) fix this?
Show answer
Scoring alone only ranks pages within a workload correctly; if candidates from both workloads still compete for one global threshold and one shared queue, the workload with far more samples simply produces more candidates above any fixed cut, regardless of their relative criticality. Domain-isolated admission gives each workload its own percentile threshold and its own queue, so BG's sampling volume can no longer crowd out FG's candidates.Misconception: that fixing the score formula is enough. The paper is explicit that scoring, admission, migration, and capacity all need isolating — fixing only one still leaves starvation possible.
Problem 3 · medium
wMLP at PEBS period 500 uses almost the same promotion budget as wMLP+LDLAT (556K vs 558K, Table 5) but recovers far less of the hot set (0.59 vs 0.87). What does this rule out as the explanation for LDLAT's benefit?
Show answer
It rules out "LDLAT just promotes fewer, less-disruptive pages" as a volume effect. Since both configurations spend almost the same number of promotions, the gap must come from which pages get promoted — LDLAT's latency threshold surfaces the genuinely displaced hot pages first, while a longer sampling period just thins out the same frequency-ranked candidate list.Misconception: that reducing promotion volume is itself the mechanism. Volume reduction is a side effect; the mechanism is latency-based selection.
Problem 4 · hard
The dCAT controller restores W_max in a single step when FG MPKI spikes, but only releases one way at a time when MPKI is low. Why is this asymmetry deliberate, and what would go wrong with a symmetric one-way-at-a-time policy in both directions?
Show answer
A missed protective allocation costs the FG immediately (real evictions, real stalls) the moment demand returns, while retaining an unneeded way only costs the BG some opportunity — a strictly smaller and more reversible loss. A symmetric one-way-at-a-time restoration would leave the FG under-protected for several 100 ms control intervals right when it needs cache most, e.g. re-entering a chase-heavy phase after a scan burst.Misconception: that a control loop should treat "give" and "take" symmetrically. Here the two directions have very different failure costs, which the algorithm explicitly encodes.
Problem 5 · medium
On sssp-kron, every evaluated tiering system (NBT, Colloid, Memtis, PACT, wMLP) lands below the NoTier baseline in the solo suite. What does this tell you about when tiering mechanisms help at all?
Show answer
sssp-kron's pointer-chasing access pattern is largely placement-insensitive — there's little tiering headroom (the gap between all-DRAM and no-migration performance) to recover, so migration bandwidth and stall spent moving pages is pure overhead. wMLP loses least (87%) because it promotes the fewest pages (0.7M vs. PACT's 0.8M); it doesn't win by being smarter about placement so much as by wasting less on migrations that don't help.Misconception: that better page-ranking always helps. When a workload has little headroom, the best any tiering system can do is minimize migration overhead, not improve placement quality.
Problem 6 · hard
ΔL2Lat (colocated minus solo L2-miss latency) is the paper's strongest predictor of slowdown (r=0.91–0.96), yet Tierce doesn't use it directly as an online signal. Why not, and what does Tierce use instead that approximates the same idea?
Show answer
ΔL2Lat requires running the same workload and placement both with and without the co-runner to get the solo baseline — production systems only ever see the colocated run, and even with a baseline, ΔL2Lat gives no page-level attribution to act on. Tierce instead reconstructs the two effects ΔL2Lat implicitly captures — LLC-induced miss inflation (space) and memory-queuing/MLP inflation (time) — separately, per page and per domain, via CAT and wMLP+LDLAT, without ever needing a solo baseline.Misconception: that the "best correlated signal" from characterization work is automatically the right online mechanism. A signal can be diagnostically ideal and operationally unusable at the same time.
Quick answers

Frequently asked questions

Tap any to expand.

Q1What exactly does Tierce add on top of PACT?▾
Tierce keeps PAC as the placement objective but replaces everything feeding it: aggregate per-tier MLP → workload-specific MLP (wMLP); uniform per-access attribution → LDLAT-selective weighting; a global admission threshold and queue → per-domain ones; and adds predictive CAT control that PACT has no equivalent of at all (Table 1).
Q2Is time aliasing the same thing as space aliasing?▾
No — they happen at different points on the request path. Space aliasing occurs at the shared LLC, before a request becomes a memory access, and changes whether it happens. Time aliasing occurs at the memory controller, after the request arrives, and changes how much it costs once it happens. Tierce needs a separate mechanism for each: CAT for space, wMLP/LDLAT for time.
Q3Why can't hardware just report per-workload MLP directly?▾
CHA/TOR counters on Intel platforms are aggregate across all cores by design, and the Thread/Core-ID filter that could isolate them uses a platform-specific encoding never mapped to Linux logical CPU IDs. Tierce calibrates that mapping once per platform by pinning a miss generator to a known CPU and matching its TOR activity to a TID encoding.
Q4Why raise LDLAT's threshold to 700 cycles instead of always using 350?▾
At small fast-tier capacity, frequency-driven promotion pressure spikes (Table 6 shows wMLP promotions growing 5.5× at a 1:9 ratio), so a stricter 700-cycle gate curbs unproductive migration when capacity is scarce. Under abundant capacity, 350 cycles captures more of the genuinely slow-tier population. LDLAT-Dyn switches between the two using per-domain eviction pressure, landing within 0.6% of whichever fixed threshold was better.
Q5Does CAT replace page migration?▾
No — they act on different things at different timescales. CAT (100 ms control interval) shapes the LLC miss stream before the tiering policy sees it; migration (5M-cycle-scale decisions in PACT's original design, ongoing in Tierce) then determines the cost of requests that still miss, over a longer horizon of changing page residency.
Q6How does Tierce compare to TPP, HeMem, Memtis, and Colloid?▾
TPP and HeMem rank by hotness/frequency for essentially single-tenant memory, but the paper treats them only as related work — neither is a direct evaluation baseline. Memtis adds dynamic page-size/classification but still scores globally. Colloid argues access latency (not hotness) is the right criterion — philosophically close to PACT/Tierce — but neither Colloid nor Memtis isolates measurement per workload under colocation. Tierce's direct evaluation baselines (§5.1/§5.5) are NUMA-balancing tiering (NBT), Colloid, Memtis, and PACT, and it beats their best margins by 22.7% (NBT), 25.9% (Colloid), and 64% (Memtis) on at least one pair.
Q7Does Tierce ever do worse than not tiering at all (NoTier)?▾
Across the 8-pair suite, no — Tierce leads NoTier everywhere, by 0.5% at worst (on sssp-kron+pr-twitter). But the paper is explicit that tiering in general needs "headroom": where migration cost exceeds placement benefit (as on the largely placement-insensitive sssp-kron solo runs), tiering policies broadly trail NoTier, and Tierce is not immune to that constraint in principle.
Q8What hardware does Tierce require, and what happens without it?▾
Intel PEBS/LDLAT, CHA/TOR counters, and CAT, validated on both Skylake and Emerald Rapids despite differing TID encodings. Analogous primitives exist on AMD (IBS/PQoS) and Arm (SPE/MPAM). Where a capability is unavailable, Tierce falls back to coarser attribution (aggregate MLP, uniform PAC weighting) while keeping domain-isolated placement — degraded signal quality, not a different architecture.
Q9Why does the BG throughput barely drop under CAT in the graph pairs (§5.3) but matters more in the LLC-allocation study (§5.8)?▾
It depends on whether the co-runner is cache-elastic. fotonik3d is bandwidth-saturating with little reusable LLC state, so releasing ways to it barely helps (2–3% cost). cc-sv-kron in §5.8 is explicitly chosen as the one cache-elastic co-runner in the suite, so a dynamic controller that releases unused FG ways can hand it a real, measurable gain (up to 50% BG throughput in the microbenchmark).
Q10What's still unresolved or left for future work?▾
Scaling time-multiplexed CHA/TOR monitoring and CAT control beyond two concurrent domains is outside the evaluation; guest-visible telemetry for virtualized deployments remains future work (PEBS/LDLAT records can expose instruction pointers and virtual addresses, so sampled data stays in the trusted host runtime); and newer chips (Intel Diamond Rapids) can attribute PEBS accesses to a memory region but still not to an execution domain, so the ownership problem persists even as hardware telemetry improves.

Core terms
TierceThe observability substrate this paper introduces: domain isolation + wMLP + LDLAT + bounded CAT, feeding PACT's PAC objective.
PAC (Page Access Criticality)PACT's score: LLC-miss count discounted by MLP-hidden latency. Tierce keeps this objective, replaces its measurement pipeline.
Time aliasingPost-LLC signal corruption: colocated workloads' queuing delay and MLP get merged into aggregate memory-controller counters.
Space aliasingPre-LLC signal corruption: shared-cache interference changes which accesses become memory requests at all.
wMLPWorkload-specific MLP, computed per core from a calibrated TID filter on CHA/TOR occupancy/cycle counters, averaged per domain.
LDLAT admissionOnly scoring PEBS load-latency samples whose realized latency clears a threshold (350 cyc hardware floor; adaptive 700 cyc software gate).
Domain-isolated placementPer-workload PAC histogram, admission threshold, migration queue, and fast-tier capacity — none shared across workloads.
sCAT / dCATStatic vs. dynamic LLC way allocation for a protected domain, the latter driven by an MPKI release/restore band.
Supporting terms
PEBS / LDLATPrecise Event-Based Sampling and its load-latency variant, tagging sampled loads with address, latency, and data source.
CHA / TORCaching/Home Agent and its Table Of Requests — the uncore stage tracking outstanding memory requests and MLP.
CAT (Cache Allocation Technology)Intel mechanism (via resctrl) for restricting which LLC ways a core may allocate into.
FG / BGForeground workload (protected, latency-sensitive) and background co-runner (best-effort).
NoTier / NoCAT / All-DRAMBaselines: no migration; unpartitioned LLC; every page kept on fast DRAM (upper-bound reference).
kdemotiondPer-cgroup-per-node kernel daemon enforcing domain-local fast-tier capacity, mirroring per-node kswapd.
MPKIMisses Per Kilo-Instruction — dCAT's default demand signal for releasing/restoring LLC ways.
SKX / EMRIntel Skylake (11-way, 13.75 MiB LLC) and Emerald Rapids (20-way, 160 MiB LLC) evaluation platforms.
