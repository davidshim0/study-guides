Judging CXL by what it saves, not just what it costs you in time

CXL memory expansion is sold on cost. Almost every paper about it is evaluated on speed. This is the plain-English story of the break-even model that finally asks the money question directly: how cheap does CXL have to be before a slowdown is worth it?

📄 "To Tier, or Not?" · Poduval, Yadalam, Swift · DIMES '26 🎓 Familiarity with memory tiering (TPP/AutoNUMA) assumed ⏱ ~25 min read
💵

A tiered system is worth deploying only when the money it SAVES on memory exceeds the value of the performance it LOSES to slower access.

1What CXL memory expansion actually is▾

A CXL type-3 device is a memory expander that plugs into a PCIe slot and presents extra DRAM capacity to the OS, without needing a free DDR channel. It's slower to access than local DRAM (a longer trip over PCIe) but can use cheaper or repurposed DIMMs, and sidesteps the limit on how many DDR channels a socket has.

Now you're ready: the whole paper is about whether that "slower but potentially cheaper" trade is actually worth making, in dollars.
2Memory tiering — hot pages stay local, cold pages migrate▾

A tiering system watches which pages are accessed often ("hot") and keeps those in fast local DRAM, while demoting rarely-touched ("cold") pages to slow CXL memory. TPP and AutoNUMA are two names for closely related Linux mechanisms that do exactly this automatically.

Now you're ready: this paper doesn't propose a new tiering policy — it takes an existing one (AutoNUMA, based on TPP) and asks a different question: was using CXL at all worth it, in cost terms?
3RSS — the number everything else is normalized by▾

Resident Set Size is simply how much memory a workload's data actually occupies. If a workload's RSS is 80 GB, and you provision 60 GB on CXL and 20 GB locally, then f = 60/80 = 0.75 — three-quarters of its footprint sits on the slow tier.

Now you're ready: every fraction in the break-even formula (f, c) is measured against RSS, not against total installed hardware.
4Cost-effectiveness as a single ratio▾

Instead of asking "is it fast?" or "is it cheap?" separately, the paper asks one combined question: how much useful work do you get per dollar spent on hardware? That's η = V(P)/Cost. A config can be fast and still score badly on η if it needed disproportionately expensive hardware to get there.

Now you're ready: everything downstream — the break-even formula, the worked examples — is just solving "when does ηtiered ≥ ηreference?"
5What a "break-even price" means, in general▾

A break-even price is the price at which two options tie. Below it, option A wins; above it, option B wins. It's a common trick for reasoning about a good whose real price you don't know: instead of guessing the price, you compute the price at which the decision flips.

Now you're ready: the paper uses exactly this trick because real CXL device pricing isn't public. It computes χ — the price CXL would need to hit — rather than assuming one.
6The three knobs: f, θ, c▾

Every break-even calculation needs exactly three measured numbers: f (how much of the workload sits on CXL), θ (how much performance was kept, 0 to 1), and c (how much CPU costs relative to the reference system's DRAM). Everything else follows algebraically.

Now you're ready: the "How It Works" tab derives χ from exactly these three numbers, and "Worked Examples" plugs real ones in.
7Why dense (3DS) DRAM makes plain capacity scaling expensive▾

A DIMM slot can only hold so much DRAM before you need denser, TSV-stacked ("3DS") chips to raise capacity further — and those cost roughly 1.5–2× as much per bit. So scaling up local memory isn't always linear in price; past a threshold, every extra GB gets pricier.

Now you're ready: this is exactly the alternative CXL competes against in the paper's "expansion" scenario — not "CXL vs. cheap DRAM" but "CXL vs. an expensive capacity upgrade."
8How to read the paper's two-row charts▾

Figure 1 stacks two rows per workload, sharing an x-axis of "fraction of RSS in fast (local) memory." The top row is normalized performance (θ); the bottom row is the resulting break-even cost (χ). Moving left means more CXL is used; moving right means more local DRAM.

The whole story in one place

The break-even model, in a nutshell

The disconnect, the formula that fixes it, and what it found on a real CXL box.

CXL memory is marketed on cost — cheaper capacity than local DRAM. But almost every tiering paper evaluates itself on performance: throughput, latency, IPC. That leaves the actual question unanswered: does the cost you save on memory outweigh the performance you lose to slower access?

The authors answer it by deriving break-even CXL cost (χ) — the highest price, relative to local DRAM, at which a tiered configuration is exactly as cost-effective as an all-local-DRAM baseline. If χ > 1, CXL is worth using even at a premium over DRAM. If 0 < χ < 1, CXL must be discounted by that much to be worth it. If χ ≤ 0, even free CXL memory wouldn't make the tiered system worthwhile — the slowdown is simply too large.

The formula needs only three measured quantities — f (fraction of capacity on CXL), θ (normalized performance), and c (CPU cost relative to reference DRAM cost) — and sidesteps the fact that real CXL device pricing is never published.

On a real CXL server running AutoNUMA (TPP-based) tiering across five memory-intensive workloads, break-even costs ranged from above local-DRAM price in favorable configurations to below zero in unfavorable ones. The common 1:8 fast:slow ratio used in many tiering papers was rarely the most cost-effective point. The strongest economic case for CXL was avoiding an expensive dense-DRAM capacity upgrade — not simply replacing cheap DRAM with cheaper CXL.

🍯 Key takeaways

  • Cost-effectiveness η = useful work ÷ total dollars spent — not performance alone.
  • Break-even cost χ answers "how cheap would CXL need to be?" without needing real CXL pricing.
  • χ = 1 − (1+c)(1−θ)/f — driven entirely by f (CXL's capacity share), θ (perf kept), and c (CPU:DRAM cost ratio).
  • In many measured configurations χ ≤ 0.5: CXL must cost half of DRAM or less to break even.
  • CXL's strongest case is expansion — avoiding costly 1.5–2× dense DRAM — not plain replacement.
  • More vCPUs can raise performance yet lower break-even cost, because memory becomes a smaller slice of total cost.
  • The 1:8 fast:slow ratio common in tiering papers is rarely the most cost-effective point.
Five everyday pictures

How to think about break-even cost

Each stands alone. Every card ends with an honest note about where the picture stops being true.

The core idea · χ as break-even

The apartment across town

A cheaper apartment (CXL) saves you rent, but costs a longer commute (the slowdown). The break-even rent discount is exactly the savings that offsets the value of your commute time — not one dollar more. Below that discount, moving is a win; above it, stay where you are.

Where it breaks: your commute cost is roughly fixed and known in advance. A workload's slowdown from CXL is measured after the fact and varies wildly by access pattern — the whole reason the paper needs real measurements, not assumptions.
Cost-effectiveness · η

A coupon with a ceiling, not a fixed price

χ isn't the price CXL will actually cost — it's the highest price it could cost and still be worthwhile, like a coupon that says "up to $X off." Whatever the real CXL price turns out to be, you compare it against this computed ceiling.

Where it breaks: a real coupon's value is known and fixed the moment you get it. χ is a derived one-sided bound computed from measurements — it tells you nothing about whether CXL's actual market price will clear that bar.
Value functions · V(P)

Business class vs. economy

A cheaper economy seat (CXL) saves money but costs you comfort and time — and how much that matters depends on what you value: total trip time, comfort, or arriving rested for a meeting. That's exactly what V(P) captures: throughput, tail latency, or SLO compliance, chosen to match what the operator actually cares about.

Where it breaks: one traveler has one value function. Real deployments run many tenants and workloads simultaneously with different SLOs, and the paper's model is applied per-workload, not aggregated across a fleet.
Sensitivity · CPU:DRAM ratio (c)

Downsizing the office, but everyone commutes farther

If headcount (CPU) is your biggest expense and rent (DRAM) is cheap, moving files to a cheaper-but-farther storage annex barely dents your budget — the commute cost dominates. But if rent is the biggest line item, that same move saves real money. This is exactly the c term: when CPU cost dwarfs DRAM cost, CXL's memory savings get diluted and break-even cost falls.

Where it breaks: office costs don't scale continuously with commute time the way compute cycles scale with memory latency — the analogy captures the direction of the effect, not its magnitude.
Expansion scenario

Buying a bigger house vs. renting a storage unit

Once your stuff outgrows your house, you either buy a bigger house (expensive per square foot — like 3DS dense DRAM) or rent a cheap offsite storage unit (CXL) for the overflow. The break-even question becomes "how cheap does the storage unit need to be, compared to the cost of upgrading the whole house?" — a much easier bar to clear than beating cheap DRAM outright.

Where it breaks: a storage unit is passive — you don't pay a "slowdown" to use it. CXL's overflow capacity is still live and accessed at runtime, so the performance penalty (absent from the storage analogy) is the real cost that must still be weighed.
The full explanation

How the break-even model actually works

From the disconnect, to the formula, to the real hardware it was tested on.

1 · The problem — cost claims, performance evidence

CXL's pitch is economic: reuse decommissioned DIMMs, avoid pin-scaling limits, add capacity per socket without buying denser DRAM. Yet almost every tiering evaluation reports IPC, latency, or throughput relative to an all-fast baseline — never dollars. A tiering policy can look like a clear win on performance charts and still be a net loss once you account for what the hardware underneath actually costs.

2 · Cost-effectiveness (η) — the combined metric

Define useful work V(P) — total operations completed, or steady-state throughput — divided by total resource cost:

η = V(P) / Total Cost
Total Cost = Σ(Ci·Ni) over CPU types  +  Σ(Cj·Nj) over memory tiers

3 · Deriving the break-even cost χ

Set the tiered system's cost-effectiveness equal to the reference (all-local-DRAM) system's, expand both cost terms, and solve for the unknown CXL price:

# cost-effectiveness must match the reference to break even
Costtiered / V(Perftiered)  =  Costref / V(Perfref)
# define θ = V(Perf_tiered)/V(Perf_ref), then Cost_tiered = Cost_ref · θ
CCPUNCPU + χCDRAMNCXL + CDRAM(RSS − NCXL)
    = θ · (CCPUNCPU + CDRAM·RSS)

# solving and simplifying (f = N_CXL/RSS, c = C_CPU·N_CPU/(C_DRAM·RSS)):
χ = 1 − (1 + c)·(1 − θ) / f
💡
Why this avoids needing a real CXL price: χ is solved for, using only things you can measure on real hardware (RSS, CPU/DRAM cost, throughput or runtime) — never an assumed dollar figure for CXL itself, which is never published by vendors.

4 · Reading the sign and size of χ

χ rangeMeaning
χ > 1CXL is cost-effective even at a premium over local DRAM's price.
0 < χ < 1CXL must be discounted below DRAM's price by that fraction to break even.
χ ≤ 0Even free CXL memory would not offset the measured slowdown.

Because f sits in the denominator, χ is most trustworthy when a meaningful share of capacity is on CXL. Near the all-local edge (f → 0), tiny performance fluctuations swing χ wildly — the paper flags these points as less informative than ones using substantial CXL capacity.

5 · Four CXL usage scenarios

The same χ derivation extends to different deployment patterns by changing what the reference system's cost represents:

  • Replacement — swap local DRAM for CXL directly; the reference pays standard DRAM cost throughout. (The base model above.)
  • Expansion — the reference must scale past standard-DIMM capacity using 1.5–2× costlier dense (3DS) DRAM; CXL competes against that premium, not against cheap DRAM.
  • Pooling — multiple servers share one CXL pool; each node pays only its share, and Pond reports 7–9% total memory savings from pooling alone.
  • Compression — a compressing CXL expander divides effective memory cost (or usage) by the compression ratio, but performance must be measured with compression overhead included.

6 · Validating on a real CXL server

The model is applied to five memory-intensive workloads (Table 1) run on a single-socket AMD EPYC 9634 server with 128 GB local DRAM and 1 TB CXL memory, under AutoNUMA (numa_balancing=2, demotion_enabled=1) — Linux's TPP-based tiering — on Linux 7.0, since real CXL hardware requires kernels newer than 6.3. Unloaded latency is ~120 ns local vs. ~250 ns CXL; read-only bandwidth is 250 GB/s local vs. 90 GB/s CXL (rising to ~115 GB/s at 1:1 read/write, since PCIe has separate read and write lanes). The default cost model assumes 1 vCPU costs the same as 2 GB of DRAM, based on AWS instance-pricing analysis.

Follow the numbers, step by step

Worked examples

The paper's own numeric example, extended three ways using its own formula.

① The paper's worked example: is 60 GB of CXL worth it?

RSS = 80 GB, 20 vCPUs, DRAM ≈ $25/GB, and — for simplicity — 1 vCPU assumed to cost the same as 1 GB of DRAM ($25). The tiered config uses 60 GB CXL + 20 GB local, and reaches 80% of the all-local-DRAM performance.

  1. f = NCXL/RSS = 60/80 = 0.75 — three-quarters of the footprint is on CXL.
  2. θ = 80% = 0.8 — the measured performance ratio vs. all-local DRAM.
  3. c = CCPU·NCPU/(CDRAM·RSS) = (25·20)/(25·80) = 500/2000 = 0.25.
  4. χ = 1 − (1+0.25)(1−0.8)/0.75 = 1 − (1.25 × 0.2)/0.75 = 1 − 0.333 = 0.667.
🍯
Verdict: this tiered config is worthwhile only if CXL costs at most two-thirds the price of local DRAM per GB — a real bar, not a trivial one to clear.

② Same workload, different CPU:DRAM cost ratios

The paper sweeps CPU:DRAM cost ratio (r = CCPU/CDRAM) from 1:1 to 8:1 in Figure 3. Re-running example ① at each ratio, holding θ=0.8 and f=0.75 fixed, shows exactly why the trend goes the way it does:

  1. r = 1 (the example above): c = 1×20/80 = 0.25 → χ = 0.667.
  2. r = 2 (the paper's own default assumption elsewhere — 1 vCPU = 2 GB DRAM): c = 2×20/80 = 0.5 → χ = 1 − (1.5×0.2)/0.75 = 0.600.
  3. r = 4: c = 4×20/80 = 1.0 → χ = 1 − (2.0×0.2)/0.75 = 0.467.
  4. r = 8: c = 8×20/80 = 2.0 → χ = 1 − (3.0×0.2)/0.75 = 0.200.

③ Why running ER at 8 threads was never worth it

ER's RSS is only 22 GB — small next to its CPU allocation. Using the paper's default ratio (1 vCPU = 2 GB DRAM, so r=2):

  1. At 8 threads: c = 2×8/22 = 16/22 ≈ 0.727. CPU cost is nearly three-quarters the size of the entire reference DRAM cost.
  2. At 4 threads: c = 2×4/22 = 8/22 ≈ 0.364 — half the CPU-cost burden of the 8-thread case.
  3. Plug either into χ = 1−(1+c)(1−θ)/f: a larger c inflates the (1+c) multiplier on any slowdown, pushing χ down for the same measured θ and f.
  4. The paper reports exactly this outcome: at 8 threads, χ ≤ 0 for every configuration tested — even free CXL wasn't worth it — which is why ER is evaluated at 4 threads instead.
⚠
Misreading to avoid: more threads gave ER higher raw performance, but lower memory-per-core makes CPU cost dominate the denominator — a faster config can still be a worse economic one.

④ Extending example ① into the expansion scenario

Suppose this same 80 GB workload exceeds the standard-DIMM capacity threshold, so the all-local reference must pay the 1.5× dense-DRAM rate on its entire 80 GB, while the tiered config's 20 GB of local memory stays under the threshold and pays the normal 1× rate.

  1. The reference's DRAM cost term grows by 1.5×, so Costref is now considerably larger for the same RSS — the all-local baseline just got more expensive to build.
  2. Because χ is defined relative to that now-pricier reference, the same measured θ = 0.8 and f = 0.75 yield a higher break-even ceiling than in example ①'s plain-replacement case.
  3. This matches the paper's own finding: Figure 2's expansion-scenario break-even costs sit uniformly above Figure 1's replacement-scenario values, across every workload tested.
🍯
Framing note: this step is illustrative — it applies the paper's described mechanism (§3.2.1, §4.3) to example ①'s numbers, rather than quoting a specific reported figure.
Test yourself

Practice problems

Try each before opening the answer. Every one ends with the misconception it checks for.

Problem 1 · easy
A workload has RSS = 100 GB. You provision 40 GB on CXL. Measured performance is θ = 0.9, and c = 0.2. Compute f, then χ.
Show answer
f = 40/100 = 0.4. χ = 1 − (1+0.2)(1−0.9)/0.4 = 1 − (1.2×0.1)/0.4 = 1 − 0.3 = 0.7. CXL is worthwhile up to 70% of DRAM's price.Misconception: forgetting that f is capacity provisioned on CXL over total RSS, not over installed hardware capacity.
Problem 2 · easy
Same formula, but θ drops to 0.5, f = 0.2, c = 0.25. Compute χ and interpret the sign.
Show answer
χ = 1 − (1.25×0.5)/0.2 = 1 − 3.125 = −2.125. Strongly negative: the slowdown is so severe that even free CXL memory would not offset it — the tiered config is uneconomical regardless of pricing.Misconception: assuming "CXL is always fine as long as it's cheaper than DRAM." A large enough performance loss makes any nonnegative price too expensive.
Problem 3 · medium
The paper found that running ER at 8 threads was never cost-effective (χ ≤ 0), yet 8 threads gave higher raw throughput than 4 threads. Explain the apparent contradiction.
Show answer
Break-even cost measures cost-effectiveness, not raw performance. More threads raise CPU cost (NCPU) relative to the fixed 22 GB RSS, inflating c. A larger c amplifies the penalty term (1+c)(1−θ) in the χ formula for any given slowdown, pushing χ toward or below zero even though θ itself might look reasonable.Misconception: that faster is always more cost-effective. Adding compute dilutes memory's share of total cost, which can make the same tiering setup a worse economic bet.
Problem 4 · medium
Why does the expansion scenario (competing against 1.5× dense DRAM) produce higher break-even costs than the replacement scenario, for the identical tiered configuration?
Show answer
χ is defined relative to the reference system's cost. In the expansion scenario, the all-local reference must pay the 1.5× dense-DRAM rate to fit the whole footprint, making Costref larger. The tiered configuration is being compared against a pricier alternative, so it can tolerate a higher CXL price and still match that alternative's cost-effectiveness.Misconception: thinking CXL's absolute cost is what matters. What matters is the cost of the next-best alternative it's displacing — cheap DRAM in one case, expensive dense DRAM in the other.
Problem 5 · hard
Show algebraically what χ equals when θ = 1 (no slowdown at all), for any f > 0 and any c. What does that tell you about χ's ceiling?
Show answer
χ = 1 − (1+c)(1−1)/f = 1 − 0 = 1, regardless of f or c. If tiering causes zero slowdown, the break-even price is exactly local-DRAM's price — never higher. This makes sense: with no performance cost at all, CXL is just as good a deal as DRAM would be at the same price, no more.Misconception: assuming a "perfect" tiering result should let CXL command a premium (χ > 1). χ > 1 can only happen when the reference's own cost structure (e.g., dense-DRAM premiums in the expansion scenario) makes local memory pricier than plain DRAM — never from performance alone.
Problem 6 · hard
The paper warns that break-even values near the all-local edge (f → 0) swing wildly and are "less informative." Explain why, using the formula's structure.
Show answer
f appears in the denominator of the penalty term (1+c)(1−θ)/f. As f shrinks toward zero — meaning almost no capacity is actually on CXL — that same small measured performance difference (1−θ) gets divided by an increasingly tiny number, amplifying any noise in θ into huge swings in χ. A configuration barely using CXL tells you little about CXL's true economic value; you need a substantial f for the measurement to be stable.Misconception: treating every point on a break-even curve as equally trustworthy. Points computed from tiny CXL fractions are numerically unstable and should be discounted.
Quick answers

Frequently asked questions

Tap any to expand.

Q1What exactly is the break-even CXL cost measuring?▾
The highest price CXL memory could carry, relative to local DRAM's price per GB, while still making the tiered system just as cost-effective as running everything on local DRAM. It's a ceiling derived from measured performance and known CPU/DRAM costs — not a prediction of CXL's actual market price.
Q2Why not just look up CXL device pricing and compute real costs directly?▾
CXL device pricing isn't public. Rather than guess, the model inverts the question: instead of "what does this cost?" it asks "what price would make this decision break even?" — which only needs measurable quantities (RSS, CPU/DRAM cost, performance), never an assumed CXL price.
Q3What does a negative break-even cost mean in practice?▾
It means the measured slowdown is severe enough that no price for CXL — not even zero — could make the tiered configuration match the all-local baseline's cost-effectiveness. The tiering setup itself, not the price of memory, is the problem in that regime.
Q4Why is the expansion scenario CXL's strongest economic case?▾
In expansion, CXL isn't competing against cheap standard DRAM — it's competing against the alternative of buying 1.5–2× costlier dense (3DS) DRAM to keep scaling local capacity. Displacing an expensive alternative is a much easier bar to clear than beating cheap DRAM outright, so break-even costs are uniformly higher in this scenario.
Q5Is the break-even model tied to a specific tiering policy like TPP?▾
No — the break-even formula is policy-independent; it only consumes a workload's measured f/θ/c under whatever policy produced them. The paper validates it using AutoNUMA (TPP-based) because that's what real, current CXL-ready kernels support, but a different policy — TPP itself, HeMem, Memtis — would simply produce a different θ curve to plug into the same formula.
Q6Why does adding more vCPUs sometimes make CXL less cost-effective, even if performance improves?▾
More vCPUs raise NCPU, which raises c = C_CPU·N_CPU/(C_DRAM·RSS). A larger c means memory is a smaller fraction of total system cost, so the dollar savings from using CXL matter less relative to the (expensive) compute being slowed down. ER is the paper's concrete example: 8 threads gave better raw throughput but a permanently negative break-even cost, while 4 threads (matching memory-per-core to the other workloads) made CXL viable.
Q7Why is the common 1:8 fast:slow memory ratio rarely the best economic choice?▾
Many tiering papers evaluate at a fixed, CXL-heavy ratio (e.g., 1 GB local for every 8 GB CXL) because it stresses the tiering policy. But the paper's break-even curves peak at intermediate fast-memory fractions — enough local DRAM to recover most performance, with just enough CXL to meaningfully cut cost. Heavy CXL ratios usually mean large performance loss for the extra capacity saved, requiring unrealistically cheap CXL to justify.
Q8Does this model account for pooling and compression, and were they measured?▾
The paper extends the formula to both as model variants — pooling by reducing each node's effective N_CXL and cost share (citing Pond's reported 7–9% total memory savings), compression by dividing CXL capacity/cost by a compression ratio — but neither was evaluated on real hardware; the paper states it lacks such devices.
Q9How does this connect to research comparing TPP, HeMem, Memtis, or Pond?▾
Those systems compete on performance — how well they classify hot/cold pages or place data. This paper sits one layer up: given any such policy's measured performance curve, it answers whether the resulting tiered deployment is worth its cost at all. It's a complementary lens, not a competing tiering mechanism — you could run the same break-even analysis on top of any of them.
