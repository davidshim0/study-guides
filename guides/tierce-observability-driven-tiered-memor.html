SOSP 2026 · A Field Guide

Giving each workload back its own stopwatch, not a shared one

Two colocated workloads share an LLC and a memory controller. Every hardware signal a tiering policy reads — misses, MLP, latency — gets blended across them before the OS ever sees it. This is the plain-English story of Tierce, the observability substrate that un-blends it.

📄 "Tierce: Observability-Driven Tiered Memory Management for Colocated Workloads" · Xu, Inceisci, Li, Zhang, Li 🎓 Assumes DRAM/NVM tiering, CXL, Linux mm background ⏱ ~25 min read
⏱️

Score every page by the stall its own workload would feel — never by the stall two colocated workloads blended together appear to feel.
Measure in isolation, enforce in isolation, only then place.

Before you begin

Quick glossary, then the paper-specific machinery

Skipping cache/tiering fundamentals — you know those. This covers the Intel uncore telemetry Tierce leans on (PEBS, LDLAT, CHA/TOR, CAT) and the two failure modes the paper names (time and space aliasing).

🔤 Quick glossary — key acronyms, up front

PACPage Access Criticality — PACT's placement score; CPU stall saved by promoting a page, discounted by MLP.
MLP / wMLPMemory-Level Parallelism (overlapping outstanding requests hides latency); wMLP = workload-specific MLP, Tierce's fix for aggregate MLP.
LLCLast-Level Cache — the shared on-chip cache both FG and BG workloads contend for before a request reaches memory.
CHA / TORCaching/Home Agent — Intel's uncore request router; its Table Of Requests (TOR) tracks outstanding requests, used to derive MLP.
PEBS / LDLATPrecise Event-Based Sampling — hardware samples LLC-miss loads; the LoaD-LATency variant also tags each sample's realized latency and data source.
CATCache Allocation Technology — Intel's mechanism (via resctrl) to partition LLC ways between cores.
FG / BGForeground (the workload tiering is trying to protect) vs. Background (a best-effort colocated co-runner).

SKX / EMRSkylake (11-way, 13.75 MiB LLC) and Emerald Rapids (20-way, 160 MiB LLC) — the two Intel server platforms evaluated.

1PACT and PAC — the objective Tierce keeps▾

PACT (ASPLOS'26, the paper's direct predecessor) ranks pages by Page Access Criticality: discount a page's observed stall cost by the MLP that was hiding it, then promote pages above the 3rd quartile of the score distribution. PACT's weakness is scope: one global score distribution, one global admission threshold, one global promotion queue, one global fast-tier budget — all shared across every colocated workload.

Now you're ready: Tierce keeps PAC as the objective (Table 1) and replaces everything beneath it — measurement, attribution, admission, LLC control — with per-workload versions.
2PEBS and PEBS LDLAT — what the hardware actually samples▾

PEBS fires a hardware interrupt on a sampled subset of LLC-miss loads and records the faulting instruction and address — enough to attribute a miss to a page, but not its latency. LDLAT is a companion PEBS facility: it only emits a record once a load's realized latency clears a programmable hardware floor, and it tags the record with that latency and its data source (L1/L2/L3/local-RAM/remote-RAM).

Now you're ready: ordinary PEBS gives you ownership; LDLAT additionally gives you realized latency and data source, for finer selectivity — Tierce sets its hardware floor to 350 cycles and layers a data-source check and per-access latency weighting on top (§4.4).
3CHA/TOR — uncore MLP, and why it's aggregate by default▾

Every LLC miss is routed through a per-slice Caching/Home Agent (CHA), whose Table Of Requests (TOR) counts outstanding requests per cycle — the raw material for MLP = occupancy/active-cycles. But physical-address hashing scatters one core's requests across all CHA slices, and the slices don't distinguish which core issued a request unless you apply a TID filter — whose encoding isn't mapped to Linux logical CPU IDs out of the box.

Now you're ready: Tierce calibrates the TID↔CPU mapping once (pin a generator, sweep TIDs, match TOR activity), then applies it globally to compute per-core, per-tier MLP (§4.3).
4CAT / resctrl — partitioning the LLC itself▾

Intel Cache Allocation Technology, controlled through the resctrl filesystem, assigns each core (or core group) a bitmask of LLC ways it may install lines into. It's a pure capacity knob — no notion of page criticality — normally used for QoS isolation, not tiering.

Now you're ready: Tierce repurposes CAT as a stabilizer upstream of placement: bound a workload's cache residency so the miss stream a tiering policy scores is not itself an artifact of co-runner eviction (§4.5).
5Space aliasing vs. time aliasing — the paper's core distinction▾

Space aliasing happens upstream, at the LLC: a co-runner's accesses evict your lines, so whether your access becomes a memory request at all depends on someone else's footprint — cache interference is indistinguishable from the effect of your own page placement. Time aliasing happens downstream, after a request reaches DRAM/CXL: queuing and MLP differ per workload, but aggregate counters report one blended number for both.

Now you're ready: every Tierce mechanism maps to exactly one of these — CAT bounds space aliasing; wMLP and LDLAT correct time aliasing (§2.3).
6kswapd/kdemotiond — why OS reclaim is already shared▾

Linux demotion is driven by per-NUMA-node kswapd daemons reacting to node-wide fast-memory pressure — reclaim is shared by every workload on a node and can't be steered per workload, independent of any userspace scoring policy.

Now you're ready: Tierce's kernel-side fix is a per-memory-cgroup kdemotiond, one daemon per cgroup–node pair, so admission/demotion/capacity enforcement never crosses a cgroup boundary (§4.6).
7SKX vs. EMR — why both platforms matter▾

SKX: 11-way, 13.75 MiB LLC, 90 ns local DRAM vs. 190 ns CXL-proxy. EMR: 20-way, 160 MiB LLC (11.6× larger), 110 ns vs. 199 ns. The 8-pair headline suite runs on SKX (comparisons to prior art); the LLC-partitioning characterization and microbenchmark run mainly on EMR, where the much bigger cache changes which mechanism dominates (§5.2).

Now you're ready: when a number cites SKX or EMR specifically, that's not noise — EMR's LLC already retains most of a workload's hot set, so CAT contributes far less there than on SKX (14% vs. 4%, §5.2).
8MPKI, L2Lat, and Probe — three ways to size a release▾

Releasing an LLC way back to a co-runner needs a demand signal. MPKI (misses per kilo-instruction) is a passive, conservative proxy for "do I still need this cache." L2Lat (average L2-miss latency) is passive but can falsely read low-demand as low-value. Probe actively withdraws a way and checks if FG throughput holds — accurate but perturbs execution.

Now you're ready: §5.8 compares all three; Tierce ships MPKI by default because an erroneous release costs the FG more than an unneeded way costs the BG.
The whole story in one place

Tierce in a nutshell

The observability gap, the four mechanisms that close it, and the numbers that result.

Tiered-memory policies decide page placement from hardware signals — access frequency, stall cost, MLP. Those signals are reliable in isolation. Under colocation they aren't: a co-runner's accesses change whether your LLC miss happens at all (space aliasing) and change how long that miss takes to service once it does (time aliasing). Existing systems, including the paper's own predecessor PACT, still read a single aggregate signal and hand every workload the same blended estimate.

Characterizing 138 colocated executions, the authors find that ΔL2Lat — the colocation-induced shift in L2-miss latency relative to a workload's solo baseline — correlates with slowdown better than any other metric (r = 0.91 across all apps, 0.96 excluding client-server workloads). But ΔL2Lat needs a solo baseline production doesn't have, and it gives no page-level attribution — it can tell you a workload is suffering, not which pages to move.

Tierce recovers that attribution online with four composed mechanisms: domain-isolated placement (private score distributions, thresholds, queues, and fast-tier budgets per workload), workload-specific MLP (wMLP) from calibrated per-core, per-tier CHA/TOR counters, latency-selective admission via PEBS LDLAT (admit samples past a 350-cycle realized-latency floor and a data-source check, then weight each by its own latency), and bounded LLC residency control via CAT, so the miss stream every other mechanism observes isn't itself distorted by a co-runner's eviction pressure.

The payoff: across 8 colocated pairs on SKX, Tierce beats PACT, the best prior art, on every pair, by 2.2% to 12.6%. Its worst case sits 0.5% above the untiered baseline and 7.4% below a pair's all-DRAM reference. Its largest margins over NUMA-balancing (NBT), Colloid, and Memtis are 22.7%, 25.9%, and 64%, respectively.

🕰️ Key takeaways

  • Colocation corrupts page-criticality signals at two points: space aliasing (LLC, before memory) and time aliasing (DRAM/CXL, after memory).
  • ΔL2Lat is the most consistent hindsight predictor of slowdown across workload classes and placements (r = 0.91–0.96); the single highest correlation measured, r ≈ 0.99, belongs to ΔL3Lat on the memory-bound subset, not ΔL2Lat. Neither can drive online placement — no page attribution, needs a solo baseline.
  • Tierce keeps PACT's PAC objective but reconstructs every input beneath it per execution domain (Table 1).
  • wMLP rescales PAC toward the FG's true overlap (median PAC 1078→1543 in one measured case) without reordering pages.
  • LDLAT concentrates a shrunken promotion budget on the slow-tier tail — 4–5× fewer promotions, more of them useful (EMR solo microbenchmark, Table 5).
  • CAT bounds upstream interference; it contributes far more on SKX's small LLC (+14%) than on EMR's large one (+4%).
  • Result: on the 8-pair SKX suite, beats PACT on every pair by 2.2–12.6%, worst case only 0.5% above NoTier.
Six everyday pictures

How to think about Tierce

Each stands alone — read in any order. Every card ends with where the picture stops being true.

Time aliasing · wMLP

Two runners, one shared stopwatch

Two joggers share a single stopwatch a bystander clicks at each finish line. The watch reports one blended pace — you can't tell which runner is actually overlapping their strides (high MLP) and which is laboring one step at a time. Tierce gives each runner their own stopwatch, started and stopped only by their own steps: wMLP.

Where it misleads: giving each runner a watch is cheap; giving each core a dedicated uncore counter isn't — hardware lacks enough counters to monitor every core-tier pair at once, so Tierce time-multiplexes across 20 ms epochs rather than truly running in parallel.
Space aliasing · CAT

A shared locker room before the race

Both runners change in the same locker room before the track. If one runner's gear is always shoved out by the other's, whether you even make it to the starting line stops being about your own pace — it's about locker contention. CAT is a reserved shelf: a fixed number of hooks each runner always keeps, so being "slow to the track" reflects your race, not the locker room.

Where it breaks: a reserved shelf that's too generous just sits empty — CAT costs real LLC capacity the co-runner could have used; on EMR's much larger LLC, the shelf barely matters (+4% vs. SKX's +14%, §5.2) because almost nothing was being lost to the locker room in the first place.
Domain isolation · §4.2

Two departments, one shared expense account

One company credit card, used by both the R&D team and the sales team. Whoever swipes more often — regardless of whose purchase actually mattered — exhausts the shared limit. Under one global promotion queue, Tierce measured a memory-intensive co-runner taking 95% of all promotions, starving a foreground whose pages scored higher per access. The fix is two separate cards, two separate limits.

Where it breaks: separate accounts don't automatically mean fair ones — each domain can still mis-size its own budget; Tierce's fast-tier capacity per domain is a fixed operator-set ratio (1:1 or 1:9 RSS split), not itself adaptive.
Latency-selective admission · LDLAT

A triage nurse, not a receptionist

A receptionist logs every visitor equally — a sprained ankle gets the same slot as a scraped knee. A triage nurse instead only pulls patients whose vitals cross a real threshold into the urgent queue, and then charts how severe each one actually is. LDLAT is the triage nurse: it only emits a sample once realized latency clears 350 cycles, double-checks the data source to catch any cache or local-memory stragglers the latency floor missed, and scores each admitted sample by its own latency — so a shrunken promotion budget goes to genuinely slow accesses rather than merely frequent ones.

Where it breaks: triage thresholds need calibrating to the patient population — too high a threshold under scarce fast-tier capacity still helps (§5.7 shows 700 cycles wins when DRAM is tight), but the "right" cutoff isn't fixed; Tierce self-tunes it from eviction pressure (LDLAT-Dyn) rather than hardcoding one value.
Bounded release · MPKI controller

A one-way ratchet with a panic button

You lend a tool back to a neighbor only when you're clearly not using it, but the moment you need it again, you take it all back in one motion — no half-measures while you're mid-project. Tierce's LLC controller is exactly this asymmetry: release one way at a time when MPKI is low, but restore the full protected allocation (W_max) in a single step the instant MPKI spikes.

Where it breaks: a neighbor who can't use the tool when it's free gains nothing from the loan — the BG throughput gains require a cache-elastic co-runner; a pure streaming BG has no reusable LLC state to exploit the released ways (§4.5, §4.7).
Characterization · ΔL2Lat

Judging a swim time without knowing the current

A swimmer's raw lap time means little without knowing whether they swam with or against a current. ΔL2Lat is "subtract out the current": take a workload's colocated L2-miss latency and subtract its own solo baseline, isolating exactly the colocation-induced shift. That difference (not the raw latency) is what correlates with slowdown at r = 0.91–0.96 across workload classes — the most consistent predictor the paper tests; the single highest value reported, r ≈ 0.99, actually belongs to ΔL3Lat on the memory-bound subset, not ΔL2Lat.

Where it breaks: you need to have swum the pool once without a current to know your baseline — ΔL2Lat is an "ideal hindsight signal" the paper uses to characterize the problem, not something production can compute online, since it needs a solo run. That's exactly the observability gap Tierce's online mechanisms exist to close without one.
The full explanation

How it actually works

Mechanism by mechanism, with the paper's key structures rebuilt as diagrams.

1 · The signal landscape — why no single counter suffices

Reconstructing PAC under colocation means recovering four dimensions for every sampled access — ownership (which workload, which page), residency (LLC or which memory tier), overlap (how much latency was hidden by MLP), and latency (realized completion time). Existing hardware mechanisms each expose a different subset at a different granularity:

MechanismOwnershipResidencyOverlapLatency
PEBS LLC-misspageLLC misses——
PEBS LDLATpagedata source—per-access
CHA/TOR—memory tierper-tier—
CAT—LLC ways——
Linux tieringpageaggregateaggregateaggregate

None is sufficient alone — Tierce composes them, and crucially runs each one per execution domain rather than system-wide (Table 2).

2 · Domain-isolated placement (§4.2)

Each execution domain gets a private score histogram, admission threshold, promotion queue, and fast-tier capacity limit. A migration worker visits domain queues round-robin for fair bandwidth, and a promotion that would exceed a domain's budget must displace one of that domain's own pages — never a neighbor's. Without this, a memory-intensive BG consumed up to 95% of all promotions in the authors' measurements, even when the FG's own pages scored higher.

3 · Workload-specific MLP — wMLP (§4.3, Algorithm 1)

For core c, MLP is the ratio of outstanding slow-tier requests to active request-cycles: MLP_c = ΔTOR_OCC_c / ΔTOR_CYC_c. A domain's wMLP averages this across its cores. Every 20 ms, Tierce derives each domain's base per-sample stall:

S_w = k · LLC-misses_w / (MLP_w · N_w · P)
# k: PACT's slow-tier base cost (cycles) — constant, cancels in the per-domain percentile
# N_w · P: total accesses represented by N_w PEBS samples at period P

for each sampled page p owned by domain w:
    PAC_w[p] += A_w,p · S_w   # A_w,p: PEBS sample count for page p
💡
wMLP rescales, it doesn't reorder. Disabling promotion and comparing aggregate vs. workload-specific MLP on identical access traces shifts the FG's median PAC from 1078 → 1543 (aggregate MLP 1.31 vs. wMLP 1.01) — the ranking within a domain is unchanged, but the scale moves closer to the domain's true overlap, which matters because PACT's shared admission threshold otherwise under-prioritizes the FG relative to its true criticality (§5.3).

4 · Latency-selective admission (§4.4)

PEBS LDLAT only emits a record once realized latency clears a hardware floor T. At T=32, cache-labeled samples represent only their delayed tail (loads blocked by dependencies), not typical hit latencies — but remote-memory accesses separate cleanly from everything else around 400 cycles. Tierce sets the hardware floor to T = 350 cycles, capturing the slow-tier population while rejecting ordinary hits before they consume sampling/processing capacity. The floor alone doesn't fully clean the stream, though: Tierce also filters admitted samples by data source to drop any remaining cache or local-memory records, and then weights each surviving sample by its own realized latency rather than scoring every admitted access the same.

5 · Bounded LLC residency control (§4.5, Algorithm 2)

Sweeping FG way-allocation across 53 colocated pairs on EMR's 20-way LLC shows wide, bimodal variation in cache sensitivity — at a 15/5 split, 38% of pairs on DRAM and 32% on CXL gain under 1%, while 26% and 40% gain at least 10%. Preventing an eviction is worth more when the avoided miss would otherwise reach the slower, more congested tier: geomean FG gain at 15/5 is 9.9% on CXL vs. 6.1% on DRAM.

// every control interval I = 100 ms
if MPKI(FG) > τ_hi (=25): W ← W_max (=15)      // restore in one step
else if MPKI(FG) < τ_lo (=10): W ← max(W−1, W_min (=5))  // release one way
else: W unchanged
apply CAT(W, W_tot − W)
🌱
An affine fit of a workload's solo way-sensitivity curve, calibrated at just two allocations, predicts its colocated curve within 2.0% mean absolute error (worst case 19%) across 106 sweeps — and in 91 of 106 cases picks the same minimal protective allocation as the measured optimum. That's the basis for W_min=5, W_max=15 of EMR's 20 ways (§4.5).

6 · Putting it together — the memory stall decomposition

Everything above targets one factor of a simple identity: Memory stall ≈ LLC misses × exposed cost per miss. CAT acts on the first factor, upstream of any placement decision. wMLP and LDLAT refine the estimate of the second factor's true, per-workload value. Migration then acts on the pages that factor identifies as worth moving. None of the four mechanisms substitutes for the others — the paper's contribution is their composition into one pipeline, not any single piece in isolation.

Follow the numbers

Worked examples

Four calculations straight from the paper's reported figures.

① Why wMLP changes PAC's scale, not its ranking

With 17.2M identical FG samples, aggregate per-tier MLP measures 1.31; wMLP measures 1.01. What happens to PAC, and why does it matter even though pages aren't reordered?

  1. PAC's per-sample stall is 𝑆_𝑤 ∝ 1/MLP_𝑤. A smaller MLP in the denominator means a larger stall estimate per sample.
  2. 1.01 < 1.31, so wMLP's stall estimate per access is larger than the aggregate's — roughly 1.31/1.01 ≈ 1.30×.
  3. Measured effect: median FG PAC moves from 1078 (aggregate) to 1543 (wMLP) — a 1.43× shift, consistent with the compression being "modest" as the paper notes (not every page scales identically, since per-sample latency also varies).
  4. Why it's not just a bigger number: PACT's admission threshold is a shared, global percentile. If the FG's true scores are compressed by an aggregate MLP that's inflated by the BG's overlap, the FG's pages fall further from that shared cutoff than they should — Tierce's fix is making the threshold per-domain too (§4.2), so the rescaling actually changes who gets admitted.
🕰️
Insight: wMLP alone, without domain-private thresholds, would just produce a bigger number scored against the same shared bar. The two mechanisms are designed to work together.

② Sizing the geomean CXL benefit of cache isolation

At the 15/5 EMR sweep, geomean FG gain over an unpartitioned LLC is 9.9% on CXL vs. 6.1% on DRAM. What does that gap tell you about where CAT matters most?

  1. 9.9% / 6.1% ≈ 1.62× — protecting a way is worth roughly 62% more when the miss it prevents would otherwise reach CXL rather than local DRAM.
  2. Why: the stall decomposition says value = (misses avoided) × (cost per miss). CAT's "misses avoided" term is the same regardless of tier; it's the "cost per miss" term — 190 ns CXL vs. 90 ns DRAM on SKX, a 2.1× gap — that inflates the payoff when the destination tier is slower.
  3. But the distribution is bimodal, not uniform: 38% of DRAM pairs and 32% of CXL pairs gain under 1% at 15 ways, while 26% and 40% gain ≥10%. The geomean hides this — some workloads have essentially no cache-timescale reuse to protect.
  4. Conclusion: no single static allocation serves every workload (§4.5) — which is exactly the motivation for the per-workload affine predictor and the dynamic controller rather than one fixed split.

③ Volume vs. selectivity in Table 5

wMLP at period 500 issues 556K promotions; wMLP+LDLAT issues 558K — almost the same budget. Why does LDLAT still win?

  1. Same budget, different outcome: p500 recovers only 0.59 of B's hot residency at 600 s; LDLAT recovers 0.87 — a 0.87/0.59 ≈ 1.47× improvement from the same number of promotions.
  2. Rate confirms it: p500's post-swap rate is 5.83 Mops; LDLAT's is 6.24 Mops — about 7% faster despite spending the identical promotion budget.
  3. What this rules out: it's not that LDLAT simply promotes less (p1000 promotes far less — 300K — and residency collapses to 0.39). It's not that LDLAT simply promotes more either (p100 promotes 2.21M for 0.92 residency, but at 4× LDLAT's cost).
  4. The actual mechanism: LDLAT directs a larger share of a given budget to the genuinely displaced hot region — the paper separately reports FG promotions reaching B's hot region rising from 9% to 40% of the (now smaller) FG total after a phase change.
💡
Takeaway: promotion quality, not promotion quantity, is the lever — the matched-budget comparison (556K vs. 558K) isolates that cleanly.

④ Reading the SOSP-wide headline numbers

Tierce beats PACT "by 2.2% to 12.6%" across 8 pairs, with the max on silo+pr-twitter at 95.6% vs. PACT's 84.9% of all-DRAM. Does that check out?

  1. 95.6 / 84.9 − 1 ≈ 12.6%. The paper reports its margins as relative gains, not percentage-point differences — 95.6 − 84.9 = 10.7 percentage points is a different quantity and isn't what's being quoted. Read as a relative gain, silo+pr-twitter is exactly the reported maximum of 12.6%, not merely close to it.
  2. Against other baselines on that same suite: the largest margins are 22.7% over NBT, 25.9% over Colloid, and 64% over Memtis (each on a possibly different pair, likely bc-urand+pr-twitter for NBT/Colloid and bc-kron+fotonik3d for Memtis per §5.5).
  3. Floor guarantee: Tierce's worst case across all 8 pairs is only 0.5% above the untiered NoTier baseline and 7.4% below that pair's all-DRAM reference (both on sssp-kron+pr-twitter) — i.e., even its worst showing never loses to doing nothing.
  4. Sanity check against promotion counts: on bc-kron+fotonik3d, PACT gives the FG only 40% of 7.7M promotions (3.0M); Tierce's domain isolation plus LDLAT filtering lands on 2.1M total while disproportionately cutting the BG's share (3.4× vs. 1.8× for the FG) — fewer total promotions, better FG share, consistent with the "quality not quantity" theme of example ③.
Test yourself

Practice problems

Each checks a specific misconception the paper's results argue against.

Problem 1 · medium
A colleague argues: "Just read the existing per-core MLP counter — it's hardware, so it's already workload-specific." What's wrong with this, given CHA/TOR's design?
Show answer
Per-core counters exist, but physical-address hashing scatters one core's requests across every CHA slice, and TOR occupancy at each slice reflects all cores whose addresses hash there — not just one. Isolating a single core requires the CHA's Thread/Core-ID filter, whose platform-specific encoding isn't mapped to Linux logical CPU IDs by default, so the OS can't use it directly without a one-time calibration sweep (§4.3).Misconception: that "per-core" telemetry is automatically workload-isolated. The hardware exposes the filter, but turning it into a usable OS-level signal is nontrivial engineering, not a free read.
Problem 2 · easy
ΔL2Lat correlates with slowdown at r=0.91–0.96 — more consistently than every other signal tested. Why can't Tierce just compute ΔL2Lat online and use it directly as the placement signal?
Show answer
ΔL2Lat is defined as colocated L2-miss latency minus the same workload's solo baseline latency. Production has no solo baseline to subtract — the workload is always colocated. Even if it could be computed, it's an aggregate, run-level number with no page-level attribution: it tells you a workload is suffering, not which pages to migrate.Misconception: that the best-correlating metric is automatically the best control signal. Correlation for characterization and actionability for online control are different requirements — ΔL2Lat satisfies the first but fails the second (§3.4).
Problem 3 · hard
On SKX, the microbenchmark shows LDLAT's throughput contribution is a "sub-1% (noise-level)" step, while on EMR it's +7%. Both platforms run the identical mechanism. Explain the gap using the two platforms' parameters.
Show answer
The difference isn't LDLAT's mechanism — it's how long the chase phase runs relative to how fast frequency-based (wMLP-only) promotion would eventually find the displaced hot set anyway. The paper states the SKX chase phase is long enough (~75 s) that frequency-based promotion recovers the hot set on its own, masking LDLAT's advantage in convergence speed. On EMR's much larger 160 MiB LLC, with its slower far-memory path, identifying costly pages early is worth more before the phase ends.Misconception: that a mechanism's measured benefit is an intrinsic property of the mechanism. It's also a property of the workload's phase length relative to the baseline's convergence time — the same mechanism can look negligible or large depending on timing.
Problem 4 · medium
Tierce's LLC controller restores W_max in a single step when MPKI spikes, but only releases one way at a time when MPKI is low. Why the asymmetry?
Show answer
The two mistakes have different costs. Releasing a way the FG actually needed immediately hurts FG performance — an error that compounds every control interval until corrected. Retaining a way the FG no longer needs merely costs the BG some unused opportunity — a much cheaper mistake. The controller is deliberately biased toward protecting the FG: fast to restore, slow to release (§4.5, Algorithm 2).Misconception: that a control loop should react symmetrically to rising and falling demand. When the two error directions have unequal cost, the correct controller is asymmetric by design, not a bug.
Problem 5 · hard
On cc-twitter, the MPKI release policy matches the static sCAT 15/5 split on both FG and BG axes — it holds the static allocation for 95% of the run. Does this mean MPKI "failed" to find savings there?
Show answer
No — it means cc-twitter genuinely needs most of its protected allocation most of the time. The paper reports it spends 61% of the run below its own "knee" (the fewest ways for 90% of full-cache throughput) under the more aggressive L2Lat policy, which released ways anyway and lost FG performance as a result. MPKI's conservatism — treating continued misses as real demand — correctly avoided releasing ways that were still needed, even though this means dCAT looks identical to a static split on this particular workload (§5.8).Misconception: that a dynamic controller should always show visible dynamism to be considered working. Correctly recognizing "this workload needs its full allocation" and holding steady is itself the correct decision, not a missed opportunity.
Problem 6 · medium
sssp-kron is described as "placement-insensitive." Every prior tiering system (NBT, Colloid, Memtis) scores below the NoTier baseline on it, and Tierce's own margin there is its smallest in the whole suite. What does this imply about when Tierce's mechanisms actually help?
Show answer
Tierce's mechanisms correct measurement and attribution errors in page placement — they can't manufacture locality a workload doesn't have. sssp-kron's low-MLP, pointer-chasing access pattern gives migration little exploitable reuse to find regardless of how accurately it's measured, so every system (migration-based or not) pays more in migration overhead than it recovers in better placement. Tierce still wins because its isolation prevents it from actively making things worse (unlike NBT/Colloid, whose hint-fault repair and unmapping overhead actively hurt), but its margin over doing nothing is necessarily thin on this workload (§5.3, §5.6).Misconception: that a strictly better observability mechanism should produce uniformly large gains everywhere. Gains are bounded by how much of the slowdown is actually a placement/attribution problem versus an inherent property of the access pattern.
Quick answers

Frequently asked questions

Tap any to expand.

Q1Is Tierce a new placement policy, or a replacement for PACT?▾
Neither, strictly — Tierce explicitly keeps PACT's PAC objective and formula. It replaces everything PACT measures that objective from: aggregate MLP becomes wMLP, uniform per-access attribution becomes LDLAT-selective, the global admission threshold becomes per-domain, and an uncontrolled LLC becomes CAT-bounded (Table 1). The paper frames its contribution as this composition, not a new scoring function.
Q2What's the actual difference between space aliasing and time aliasing?▾
Space aliasing happens at the LLC, before a request reaches memory: a co-runner's eviction can determine whether your access becomes a memory request at all. Time aliasing happens after a request reaches DRAM/CXL: your queuing delay and MLP are blended with the co-runner's in aggregate counters. CAT addresses the first; wMLP and LDLAT address the second.
Q3Why calibrate the TID filter instead of just using existing per-core MLP counters?▾
Per-core counters exist but don't isolate a core's uncore (CHA/TOR) activity, because address hashing scatters one core's requests across all CHA slices. The TID filter can isolate a core's slice-level activity, but its platform-specific bit encoding isn't pre-mapped to Linux CPU IDs — Tierce calibrates this mapping once per platform by pinning a generator workload and sweeping TID values until TOR activity matches it.
Q4Why 350 cycles for the LDLAT hardware floor specifically?▾
Characterizing the LDLAT latency CDF by data source (Fig. 5) shows remote-memory accesses separating cleanly from cache-hit classes around 400 cycles. Setting the floor to 350 captures essentially the whole slow-tier population while rejecting typical hits before they consume PEBS/software processing capacity. The threshold alone isn't the whole admission step, though — Tierce also filters by data source to remove any remaining cache/local-memory records and weights each surviving sample by its own realized latency (§4.4).
Q5Does the LDLAT threshold ever change at runtime?▾
Yes — LDLAT-Dyn. The 350-cycle hardware floor is fixed, but a software gate toggles between accepting everything above 350 or only above 700 cycles, based on each domain's EWMA-smoothed eviction pressure, checked every 30 s with a 1 s emergency override. It lands within 0.6% of whichever fixed threshold would have been better, without retuning the sampling period (§5.7).
Q6Why does domain isolation need separate queues and capacity, not just separate scores?▾
Separate scores alone don't stop a high-volume co-runner from consuming a shared promotion queue or shared fast-tier budget. The paper measured a memory-intensive BG taking 95% of all promotions under a single shared queue even when the FG's pages scored higher — the resource contention is structural, not just a scoring artifact.
Q7How does CAT interact with page migration — don't they fight each other?▾
They operate on different timescales and different factors of the same identity (memory stall ≈ misses × cost-per-miss). CAT's 100 ms control loop changes the miss stream upstream, before a tiering decision is made; migration then determines the cost of whatever still misses, over a longer horizon, as page residency changes. CAT doesn't decide what to migrate; it stabilizes what migration observes.
Q8Why does Tierce default to MPKI over L2Lat or active probing for LLC release decisions?▾
§5.8 compares all three on five foregrounds against a cache-elastic co-runner. MPKI improves on both FG and BG axes for 4 of 5 workloads; L2Lat is more aggressive and gives up 2.2–6.6 FG points for 3.0–10.0 BG points; Probe is accurate but perturbs execution by actively withdrawing ways. Tierce ships MPKI because the controller treats an erroneous release as costlier than unnecessary retention, and MPKI is the most conservative of the three passive signals.
Q9What are the main limitations the authors acknowledge?▾
The evaluation uses an emulated CXL tier (remote NUMA node), so device/controller/link effects aren't isolated. The LLC way-allocation characterization (sweep, affine predictor, release-signal study) runs only on EMR's 20-way LLC; SKX uses a fixed split without repeating that analysis. Scaling the time-multiplexed CHA/TOR monitoring and CAT controller beyond two concurrent domains is outside the evaluation. Tierce also assumes a trusted host/hypervisor deployment, since PEBS/LDLAT records can expose instruction pointers and virtual addresses.
Q10Does this generalize beyond Intel hardware?▾
The prototype uses Intel PEBS/LDLAT, CHA/TOR, and CAT specifically, validated across SKX and EMR's differing TID encodings. The paper notes analogous primitives exist on AMD (IBS/PQoS) and Arm (SPE/MPAM); where a capability is unavailable, Tierce falls back to coarser attribution (e.g., aggregate MLP) while preserving domain-isolated placement — degrading gracefully rather than requiring the full mechanism set.
Q11When does Tierce's LLC isolation actually cost the co-runner anything?▾
Little, in the evaluated pairs — on three EMR colocations the static 15/5 CAT partition reduced BG throughput by only 2–3% relative to wMLP+LDLAT, because the streaming co-runner (fotonik3d) is bandwidth-bound, not LLC-capacity-bound, so ways taken from it cost little. Against a cache-elastic co-runner, over-allocation can meaningfully cost the BG, which is why the bounded dynamic controller exists rather than a permanent static split (§4.5, §5.8).
