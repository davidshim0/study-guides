DIMES 2026 (Workshop) · A Field Guide

One address space can hold two personalities — give each its own policy

A single program can have a scan-heavy region and a stay-hot region at the same time. Tiering systems that learn one global threshold over the whole address space can't tell them apart. This is the plain-English story of REGENT, a controller that splits the address space by behavior first.

📄 "Regional Policies for Memory Tiering Systems" · Coffey et al., UW-Madison / UT Austin / Google 🎓 Assumes basic tiering/CXL vocabulary — primers cover the rest ⏱ ~22 min read
🗺️

Don't fit ONE policy to a mix of access patterns — split the address space by pattern, and give each piece its own policy instance.
Even the same simple heuristic, run per-region, beats one global instance of a smarter one.

1Fast tier, slow tier, and why tiering exists▾

DRAM is fast but expensive; CXL-attached memory is denser and cheaper but slower to access. A tiering system keeps frequently-used ("hot") pages in the fast DRAM tier and lets cold pages sit in the slow CXL tier, moving pages between them as behavior changes.

Now you're ready: REGENT is about deciding which pages get fast-tier space — the same question every tiering policy answers, but here answered separately per region.
2Tiering heuristics: recency vs frequency▾

A recency heuristic promotes/demotes based on how recently a page was touched; a frequency heuristic ranks pages by how often they're touched. Prior work found recency suits strided scans and frequency suits skewed distributions — no single heuristic is best everywhere.

Now you're ready: REGENT doesn't invent a new heuristic in this paper — it shows that giving each pattern its own instance of even the same heuristic already helps.
3PEBS sampling and idle-page tracking▾

Watching every memory access would be far too slow. PEBS lets hardware sample a subset of accesses cheaply; idle-page scanning checks page-table access bits periodically. The paper treats the classification step built on top of these signals as infrequent and off the application's critical path; it does not separately measure whether the sampling mechanisms themselves add overhead to the running program.

Now you're ready: REGENT's per-page "active/dormant duration" features are built from this same sampled access stream.
4Huge pages and page profiles (2 MB units)▾

Memory is often managed in 2 MB huge pages rather than 4 KB pages, to reduce bookkeeping overhead. REGENT monitors and classifies memory at this same 2 MB granularity, calling each unit a page profile.

Now you're ready: "a region" in this paper is a set of 2 MB page profiles sharing a classifier label — not necessarily contiguous in memory.
5Why one address space can have two behaviors▾

A single program can allocate one data structure it scans sequentially and another it accesses in a skewed, bursty way — at the same time. A global tiering policy sees one blended access stream and must pick one set of thresholds for both.

Now you're ready: the paper's motivating examples are MERCI (embedding lookup + output scan) and Spark ALS — both mix a scan with a hot table.
6The fast-tier ratio, the paper's main knob▾

Evaluations vary the fast-tier ratio: fast-tier capacity divided by the workload's total memory footprint. A ratio of 0.1 means only 10% of the data can fit in DRAM at once — severe pressure; a ratio ≥1.0 means everything fits.

Now you're ready: REGENT's biggest wins appear at low ratios, where every promotion decision is contested.
The whole story in one place

REGENT in a nutshell

The problem, the two features that fix it, and how the pieces connect.

Tiering policies — even adaptive ones like Memtis or ARMS — apply one set of thresholds to an entire process's address space. But a single program can contain multiple distinct access patterns at once: a table read in a skewed, bursty way alongside a buffer swept sequentially. One global policy can't fit both, because pages from unrelated patterns end up competing directly for the same fast-tier space.

REGENT fixes this by partitioning the address space into regions by access pattern and running an independent tiering policy per region. It discovers regions automatically, without application hints, from two features measured per 2 MB page profile: active duration (how long a page stays busy) and dormant duration (how long it stays quiet). A simple 4-quadrant binning classifier — motivated by an earlier online-clustering approach, BIRCH — assigns each page profile a label, and a fast-tier allocator adapted from MTTM splits DRAM capacity across the resulting regional policies.

The result, on a microbenchmark combining a Zipfian region and a sequential-scan region: giving each region the same simple frequency heuristic, separately, matches Memtis at low memory pressure and beats it under high fast-tier pressure — because the gain comes from removing cross-region competition, not from a smarter heuristic.

🍯 Key takeaways

  • Adapting over the address space (per-region policies) is a distinct axis from adapting over time (one global adaptive policy).
  • Region features are active duration and dormant duration — timing (when a page is touched), not hotness (how much).
  • Both features are log-scaled and capped at 60 profiling intervals (~60 s), bounding the embedding to roughly [0, 4.09].
  • A fixed 4-quadrant binning classifier (threshold ≈ e ≈ 2.7 s per axis) matches BIRCH's labels at far lower cost.
  • New/unclassified pages sit in a fallback region so every page is always managed by some policy.
  • Labels are sticky: reclassification happens only after ~30 s of inactivity, not on every access-pattern blip.
  • A single instance of the same simple frequency heuristic, split by region, matches/exceeds Memtis on the paper's microbenchmark — the gain is from partitioning, not from smarter heuristics.
Five everyday pictures

How to think about REGENT

Read in any order. Each ends with where the picture stops being literally true.

The core idea · Regions vs one queue

Two checkout lines, not one

A grocery store with a 3-item express line and a full-cart line moves faster than one merged queue, even using the identical checkout process at each register. Sorting shoppers by type removes the interference. REGENT's regional SF policies use the exact same heuristic as global SF — the gain is purely from separating the "carts."

Where it breaks: a store manager decides the lines in advance; REGENT must discover which shopper belongs where, at runtime, from behavior alone.
Binning vs BIRCH · Pre-labeled sorting

A sorting bin vs a filing clerk

A filing clerk (BIRCH) reads each new document and decides where it fits relative to everything filed so far — flexible but slower. A pre-labeled 4-bin sorting tray (binning) just checks two thresholds and drops the item in a corner — instant, if you already know documents cluster into four types.

Where it breaks: the tray only works because REGENT already ran the clerk (BIRCH) across many workloads and found its centroids tend to land in the same four corners, with binning producing labels similar to BIRCH's on those tested workloads; a genuinely new feature space would need the clerk again.
The features · Timing, not intensity

Reading a tide chart

A tide chart tells you when the water rises and falls and for how long — not how much cargo is on any given wave. REGENT's active/dormant duration features are the same kind of measurement: how long a page stays busy, how long it stays quiet, regardless of exactly how many accesses land in that busy stretch (that's hotness, a separate question left to the region's policy).

Where it breaks: tides are perfectly periodic; page access bursts are not, so REGENT must average over each active/dormant stretch rather than reading one clean cycle.
Cold start · The fallback region

The new-hire orientation pool

A new employee doesn't get assigned to a team on day one — they sit in a general orientation pool while managers observe their work. Likewise, a newly touched page sits in REGENT's fallback region, managed by some default policy, until it accumulates enough repeated accesses to be profiled and classified.

Where it breaks: the orientation pool is temporary for everyone; a page that never gets touched again stays in the fallback region forever, simply because it never earns a real label.
Fast-tier sharing · MTTM allocator

Splitting office floor space by department

A building manager doesn't let every department claim desks first-come-first-served; they set a floor-space budget per department based on how much each needs. REGENT's fast-tier allocator, adapted from MTTM, does the same across regions within one program, apportioning capacity using MTTM-like sensitivity metrics and enforcing the split with watermarks checked before promotions.

Where it breaks: MTTM was built to split space between separate tenants (processes) with clean identities; REGENT must first figure out where the "department boundaries" are inside a single address space, which MTTM never had to do.
The full explanation

How it actually works

From raw access samples to a fast-tier allocation, section by section.

1 · The problem — one policy, one set of thresholds

Existing tiering systems, even adaptive ones like Memtis and ARMS, apply a single internal threshold (or a single learned model) across an entire process's address space. When a workload like MERCI or Spark ALS mixes a skewed, stay-hot table with a sequentially scanned buffer, the policy sees one blended stream and must compromise — but a threshold tuned for one pattern is wrong for the other.

🌱
Concretely: MERCI reads embedding vectors from a large table in an irregular order (stay hot) while filling an output buffer in scan order (touch once). REGENT's online region identification labels the table "Active" and the output scan "Transient" — automatically, from access timing alone.

2 · Features — active duration and dormant duration

From the PEBS sample stream for a page, REGENT tracks the signal's velocity (rate of change in access activity). Active duration = average time between a positive spike (activity ramping up) and the next negative spike (ramping down). Dormant duration = the reverse — time between a drop and the next rise.

a = mean(time from activity-up spike → activity-down spike)
d = mean(time from activity-down spike → activity-up spike)
# both logged, both capped at 60 profiling intervals (1s each) → bounded to [0, ln 60] ≈ [0, 4.09]
💡
Why cap and log? Capping bounds the embedding space regardless of how long a page happens to stay idle; taking the log turns "orders of magnitude" differences in duration into comparable distances, and because durations are absolute (not workload-normalized) the same coordinate means the same thing across every workload.

3 · Classifying — BIRCH, then a fixed binning scheme

REGENT's first classifier was BIRCH, an online clustering method suited to streaming, one-page-at-a-time data with an unknown number of clusters (unlike k-means or agglomerative clustering, which need the full dataset and/or a preset cluster count up front). Running BIRCH across many workloads showed its centroids concentrating in the corners of the active/dormant space — pages are predominantly active or predominantly dormant, rarely in between.

That observation is encoded directly as binning: four quadrants split at (1.0, 1.0) in log-seconds (≈2.7 s raw per axis) — Bursty, Stable, Active, Transient (definitions in the quadrant figure on the previous tab). Binning needs no model state and no per-query update, so it is far cheaper than BIRCH at the same labeling outcome on tested workloads. BIRCH remains the fallback if the feature set later grows beyond this bounded 2-D space.

4 · Region lifecycle — fallback, profile, classify, stick

A newly discovered page starts in a fallback region, managed by a default policy, so every page is always covered. Once it has received enough repeated accesses (e.g. 10), REGENT begins profiling it; once enough samples accumulate, the classifier assigns a label. That label is sticky — REGENT does not re-profile on every access-pattern blip — until the page is freed, or until it goes without accesses for an extended period (currently 30 s), which triggers a fresh profiling pass on the assumption the workload has moved to a new phase.

5 · Sharing fast-tier capacity and migration bandwidth

Once regions exist, REGENT must decide how much DRAM each region's policy gets. It adapts MTTM's DRAM-sensitivity metrics — built for splitting a fast tier across separate processes — to split fast-tier capacity across regions within one process, enforcing the split as watermarks checked before promotions and triggering demotions if a region exceeds its share. REGENT does not currently enforce a migration-bandwidth quota across regions, though its shared migration mechanism could support one.

⚠
A real limitation: mechanisms shared across regional policies — a single PEBS sample rate, system-wide bandwidth counters used by ARMS — are not region-specific. Two regional ARMS instances currently see the same global bandwidth signal, which can cause interference the paper flags as an open challenge.
Follow the numbers, step by step

Worked examples

Four calculations straight from the paper's own numbers.

① Classifying one page with binning

A page has active duration 8 s and dormant duration 1.5 s. Which quadrant?

  1. Take logs: ln(8) ≈ 2.08; ln(1.5) ≈ 0.41.
  2. Compare to the threshold at 1.0 (not 0!): 2.08 ≥ 1.0 → active-axis is "high." 0.41 < 1.0 → dormant-axis is "low."
  3. Quadrant: a≥1, d<1 → Active — predominantly busy, only brief quiet spells.
🍯
Common trap: the raw-second threshold isn't 1 second — it's e¹ ≈ 2.7 s, because the quadrant split happens in log-space at 1.0.

② The cost of BIRCH vs binning on MERCI

MERCI made ≈9,000 inferences over 2 MB huge pages. Binning averages 52 ns/inference; BIRCH averages 9 µs/inference.

  1. Total binning time: 9,000 × 52 ns ≈ 468 µs for the whole run.
  2. Total BIRCH time: 9,000 × 9 µs ≈ 81 ms for the whole run.
  3. Ratio: BIRCH costs ≈173× more per inference on average — and its worst case is far heavier still: max 2 ms vs binning's max 12.7 µs.
💡
Both are still cheap relative to a workload running for seconds to minutes, and classification is infrequent and off the critical path — which is why the paper reports no performance difference despite the cost gap.

③ How small is the memory overhead?

Page metadata costs at most 384 B per 2 MB huge page.

  1. Express as a fraction: 384 B ÷ (2 × 1024 × 1024 B) = 384 ÷ 2,097,152 ≈ 0.018% of the page it describes.
  2. Binning adds nothing further — no per-page model state.
  3. BIRCH's model is a single shared structure the paper measures at under 1 KB total, in their bounded active/dormant feature-space setup.
🍯
Insight: region identification is essentially free in memory — the interesting cost is the classification-time comparison worked out in ②, not storage.

④ Reading the microbenchmark's two regimes

Two 4 GB regions (Zipfian + sequential) → 8 GB total footprint. What happens at fast-tier ratio 0.5 vs 0.1?

  1. At ratio 0.5: fast tier = 0.5 × 8 GB = 4 GB — exactly one region's worth. Global SF ranks pages from both regions together, so as the scan sweeps forward its freshly-touched pages keep bumping warm Zipfian pages out, then get evicted themselves — the paper's observed thrashing.
  2. At ratio 0.1: fast tier = 0.1 × 8 GB = 0.8 GB — severe pressure. Memtis's histogram-threshold approach is reported as too conservative here, under-using the scarce fast tier relative to what regional policies achieve.
  3. Regional binning/BIRCH gives each region its own ranking and its own MTTM-derived share, so the two regions never compete for the same slots — matching Memtis at low pressure, exceeding it as pressure rises.
💡
This is the paper's central claim, isolated: the win comes from where the comparison happens (within a region vs across all pages), not from a better ranking formula.
Test yourself

Practice problems

Try each before opening the answer.

Problem 1 · easy
Why doesn't REGENT just use /proc/{pid}/smaps virtual memory areas as its regions?
Show answer
VMA boundaries are set by the memory allocator, not by data structure or access pattern. A high-performance allocator like TCMalloc often pre-allocates large chunks for later use, so a single mapping can contain multiple data structures with completely different access patterns — smaps can't separate them.Misconception: assuming a memory-map boundary implies a data-structure or behavior boundary. It only reflects allocator layout.
Problem 2 · medium
A page has active duration 3 s and dormant duration 6 s. Which quadrant, using the actual (log-space) threshold?
Show answer
ln(3) ≈ 1.10 ≥ 1.0 → active-axis "high." ln(6) ≈ 1.79 ≥ 1.0 → dormant-axis "high" too. Both ≥ 1.0 → Stable: the page tends to hold whatever state it's in, active or dormant, for a while.Misconception: comparing 3 s and 6 s directly to a "1 second" threshold. The threshold applies to the log of the duration; in raw seconds it's ≈2.7 s, not 1 s.
Problem 3 · medium
Why cap active/dormant durations at 60 profiling intervals before taking the log, instead of using the raw duration directly?
Show answer
Capping bounds the feature space to a fixed range (≈[0, ln 60] ≈ [0, 4.09]) regardless of how extreme any one page's dormant period gets, so the classifier's four quadrants stay meaningful and comparable no matter how long a program runs. Because durations are absolute rather than workload-normalized, the same coordinate carries the same meaning across every workload.Misconception: that durations are normalized relative to each workload's typical behavior. They're absolute (capped) seconds, on purpose.
Problem 4 · hard
A region repeats the pattern A→B→A→B→A→B every few seconds. Why does REGENT's "sticky" labeling not relabel it on every transition?
Show answer
REGENT profiles the first pattern it sees, classifies once, and stops collecting features — the label sticks until the page is freed or goes 30 s without an access. Relabeling on every A→B flip would relearn behavior the system has already seen and add overhead for no benefit, since the region keeps repeating the same two states rather than genuinely moving to a new phase.Misconception: that more frequent reclassification is always more "accurate" or adaptive. For a repeating pattern it's pure wasted work; sticky labeling assumes recurrence, and only reclassifies after evidence of a real phase change (extended idleness).
Problem 5 · medium
PageFlex also runs per-region policies, but doesn't need an explicit capacity allocator the way REGENT needs its MTTM-based one. Why?
Show answer
PageFlex manages paging, where pages are brought into memory only on demand — contention for memory capacity is resolved implicitly by demand paging itself, and PageFlex expresses regional differences as per-region reclamation thresholds. Tiering is different: slow-tier pages remain directly accessible without a fault, so promotion is discretionary, not forced. There's no equivalent trigger, so REGENT must explicitly decide how much fast-tier space each region's policy gets.Misconception: that tiering and paging face identical resource-contention problems just because both split a fixed capacity across regions. Paging's on-demand fault model provides implicit arbitration that tiering lacks.
Problem 6 · hard
At fast-tier ratio 0.5, why does global SF thrash while regional binning-SF does not, even though both use the identical frequency heuristic?
Show answer
Global SF ranks pages from the Zipfian region and the sequential region in one combined list. As the scan sweeps forward, its just-touched pages look "hot" enough to bump warm Zipfian pages out of the fast tier, then get swept past and evicted themselves — a cycle of promotion and demotion (thrashing). Binning gives each region its own ranking and its own share of the fast tier, so the scan's pages are never compared against the Zipfian region's pages at all; the comparison that causes thrashing simply doesn't happen.Misconception: that the improvement comes from a smarter ranking algorithm. Both configurations use plain SF — the entire effect is from removing the cross-region comparison.
Quick answers

Frequently asked questions

Eight questions newcomers ask most.

Q1What does REGENT solve that an adaptive policy like Memtis or ARMS doesn't?▾
Memtis and ARMS adapt over time — their thresholds shift as overall access behavior changes — but they still apply one set of thresholds to the whole address space at any given moment. REGENT adapts over the address space as well, running a separate policy instance per detected access pattern, so two simultaneous patterns don't have to share one threshold.
Q2How is a REGENT "region" different from a Linux VMA or a DAMON region?▾
VMAs are defined by the memory allocator's layout, not access behavior. DAMON groups pages by similar total access frequency (via PTE access-bit rates), which correlates with "how hot" but not with "what kind of pattern." REGENT's regions group pages by access pattern — active/dormant timing — which the paper found neither abstraction captures well.
Q3What exactly are active duration and dormant duration?▾
Active duration is the average time between a page's access activity ramping up and then ramping back down (a positive-then-negative velocity spike); dormant duration is the reverse — time between a drop and the next rise. They describe timing, not intensity: a page read steadily but infrequently is "active" without being "hot."
Q4Why did REGENT move from BIRCH to a fixed 4-quadrant binning classifier?▾
Running BIRCH across many workloads showed its cluster centroids consistently landing in the corners of the active/dormant feature space — pages are predominantly active or predominantly dormant. Since that structure was consistent, REGENT encodes it directly as four fixed quadrants, which need no model state and no per-query update, at the same labeling outcome on tested workloads.
Q5How does REGENT avoid reclassifying pages constantly?▾
Labels are "sticky": a page is profiled once, classified, and keeps that label until it's freed or goes roughly 30 seconds without an access, which triggers a fresh profiling pass under the assumption the workload has moved to a new phase.
Q6How does REGENT decide how much fast-tier memory each region gets?▾
It adapts MTTM's DRAM-sensitivity metrics — originally built to split a fast tier across separate tenant processes — to instead split fast-tier capacity across regions within a single process's address space, enforcing it via watermarks checked before promotions.
Q7Is REGENT's performance win from smarter per-region heuristics?▾
Not in this paper. The microbenchmark deliberately runs the same simple frequency heuristic in every region; the gain comes purely from partitioning, which prevents pages from unrelated access patterns from competing for the same fast-tier capacity. Specializing each region's heuristic to its pattern is explicitly future work.
Q8How is REGENT different from PageFlex, since both apply "regional" policies?▾
PageFlex applies per-region paging policies via eBPF, but regions arrive as application-provided hints, and it leaves automatic region discovery to future work; it also resolves capacity contention implicitly through demand paging. REGENT discovers regions automatically from runtime access patterns with no application hints, and — because tiering has no demand-paging trigger — must explicitly apportion fast-tier capacity itself.

Related work

AMP: Adaptive Page Migration Policy with Huge Pages medium

Heo, Wang, Cui, Huh, Zhang · IEEE TC · 2022

Identifies which heuristic (frequency/recency/random) suits which workload and switches over time; operates at cgroup granularity, not within a single process's simultaneous patterns.

PageFlex medium

Yelam et al. · USENIX ATC · 2025

Per-region paging policies via eBPF, using application-provided region hints; contention resolved implicitly through demand paging.

Mira: A Program-Behavior-Guided Far Memory System hard

Guo, He, Zhang · SOSP · 2023

Also dedicates memory to different access patterns, but derives regions via static program analysis and recompilation rather than runtime classification of an unmodified binary.

DAOS / DAMON medium

Park, Bhowmik, Uta · HPDC · 2022

Linux's access-aware region monitor; groups by similar access frequency and age, which the paper found does not correlate with access pattern.

MTTM: Dynamic Fast Memory Partitioning hard

Lee, Choi, Kwon · EuroSys · 2026

Partitions a fast tier across tenant processes using DRAM-sensitivity metrics; REGENT adapts the same metrics to partition within one process's regions.

BIRCH: An Efficient Data Clustering Method hard

Zhang, Ramakrishnan, Livny · ACM SIGMOD · 1996

The original online clustering algorithm REGENT used before settling on the fixed binning scheme it motivated.

Memtis medium

Lee, Monga, Min, Eom · SOSP · 2023
