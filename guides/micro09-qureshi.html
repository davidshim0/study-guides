Don't track the hot lines — just keep all of them moving

Phase Change Memory packs more bits per chip than DRAM, but every cell can only be rewritten a few tens of millions of times before it wears out — and real programs hammer a handful of lines far harder than the rest. This is the plain-English tour of Start-Gap, a wear-leveling scheme that needs no write-count table and no indirection lookup — just two small registers and a spare line that never stops sliding.

Don't spend megabytes tracking which lines are hot — just shift every line past a single moving gap, so no line can sit still long enough to wear out.

Eight ideas the paper assumes you know

Each card clears up one concept Start-Gap builds on. They're collapsed — tap any to open. Read in order the first time, or jump to whatever looks unfamiliar.

Start-Gap's own mechanism neutral machinery/math the failing baseline / the problem
1Phase Change Memory (PCM), in one paragraph▾

PCM stores a bit by heating a chalcogenide material into either a crystalline (low resistance) or amorphous (high resistance) state. It's roughly 2–4x slower than DRAM for reads, but up to 4x denser, which makes it an attractive way to grow main-memory capacity beyond what DRAM's power and cost budget allows.

Now you're ready: density is the appeal, but PCM comes with a catch DRAM doesn't have — see the next card.
2Write endurance: PCM cells wear out▾

Each PCM cell can endure only about 107–108 writes before it can no longer reliably switch states. That's far more than Flash can survive per cell (104–105), but still low enough that, at realistic write traffic, a PCM-based main memory could wear out within a few years even under ideal conditions.

Now you're ready: "ideal conditions" here means writes spread perfectly evenly across every cell — which real programs don't do, as the next card shows.
3Non-uniform write traffic▾

Real workloads write to a small number of memory lines far more often than the rest. In the paper's own measurement of the commercial db2 workload, one line was written 9,175 times while the average line was written only 64 times — a huge skew, all concentrated on a handful of physical cells.

Now you're ready: those few heavily-written lines fail first, long before the memory's "expected" lifetime — cutting real achievable lifetime to a fraction of the theoretical maximum.
4Wear leveling: the general idea▾

Wear leveling is any mechanism that redistributes writes so that all cells wear out at roughly the same rate, instead of a few hot cells failing while the rest are barely used. Flash storage has used wear leveling for years; the question this paper asks is how to do it cheaply enough for main memory, where every access is latency-critical.

Now you're ready: the "cheaply enough" part is the whole design problem — see the next card for why the obvious approach doesn't qualify.
5Table-Based Wear Leveling (TBWL) — the existing approach▾

The standard technique (borrowed from Flash) tracks a write count per block and periodically remaps heavily-written blocks to less-worn ones via a separate indirection table. At PCM's fine 256-byte line granularity, this table has to cover tens of millions of lines — many megabytes of storage — and must be consulted on every single memory access, adding real latency.

Now you're ready: this is the baseline Start-Gap is designed to beat — same goal, without the table.
6Algebraic address mapping (no table needed)▾

Instead of looking up a physical location in a table, an algebraic mapping computes it directly from the logical address using a small, fixed arithmetic formula and a couple of registers. No storage scales with memory size, and no table lookup sits on the access-latency critical path.

Now you're ready: this is the key insight the whole paper is built on — replace the table with a formula.
7Address-space randomization (block ciphers, Feistel networks)▾

A Feistel network is a simple, well-studied way of building a reversible (one-to-one) scrambling function — it's the structure behind DES and other block ciphers. Applied to an address instead of a plaintext message, it can shuffle nearby addresses far apart from each other while still allowing the original address to be recovered exactly.

Now you're ready: Start-Gap borrows this idea not for secrecy, but to break up spatial clusters of heavily-written lines before wear leveling ever sees them.
8Denial-of-service via memory wear-out▾

Because a PCM cell has a hard write limit, a program that deliberately writes to the same address over and over can push that cell past its endurance limit and disable it permanently — a more severe outcome than an ordinary denial-of-service attack, since the resource doesn't come back once it's dead.

Now you're ready: this is "Problem 2" the paper tackles — a security question that only exists because memory now has a lifespan.

The whole story in one place

Start-Gap in a nutshell

The problem, the mechanism that fixes it, and how it all connects.

PCM's write endurance is high enough that a system with perfectly uniform writes would last 4–20 years. But real workloads aren't uniform — the paper measures a baseline 16GB PCM system achieving only 5% of its theoretical maximum lifetime, because a small number of heavily-written lines fail decades before the rest of memory is anywhere near worn out. Table-Based Wear Leveling, the standard fix borrowed from Flash, works — but it needs a write-count table and an indirection table for every line, scaling to hundreds of megabytes at PCM's fine 256-byte granularity, plus a table lookup added to every memory access's critical path.

Start-Gap's insight: replace the table with algebra. Add one spare line (GapLine) to memory, forming a circular buffer, and track just two small registers — Start and Gap. Every ψ writes to memory (ψ=100 in the paper), Start-Gap performs a Gap Movement: it copies one line's contents into GapLine and decrements Gap, nudging that line into a new physical slot. Once Gap has swept through every line in memory — a Gap Rotation — every single line has shifted by exactly one physical position, and Start increments to record it. The physical address for any logical address is now just ((LA + Start) mod N), adjusted by one if it's past Gap — a handful of logic gates, no storage that scales with memory size, and no lookup table on the critical path.

Because Gap only ever swaps a line with its immediate physical neighbor, Start-Gap alone reaches only 53% normalized endurance — heavily-written lines that happen to sit near each other in the address space (which real workloads' hot lines usually do) keep swapping with each other rather than with cold lines. The fix is address-space randomization: run every logical address through a fixed, invertible scrambling function (a RIB matrix or a three-stage Feistel network) before Start-Gap ever sees it, breaking up spatial clusters of hot lines. Randomized Start-Gap reaches 97% normalized endurance with under 100 bytes of total storage. A separate concern — a targeted write attack can kill a single line in under a minute, and randomization alone doesn't stop that — is addressed by Region-Based Start-Gap (RBSG), which partitions memory into many small, independently-rotating regions so an attack can't outpace the region's own Gap Movement.

🍯 Key takeaways

  • Non-uniform write traffic cuts a PCM system's real achievable lifetime to just 5% of the theoretical maximum — a 20x reduction from what uniform writes would achieve.
  • Start-Gap's insight: replace the write-count table and indirection table of existing wear-leveling with an algebraic mapping — two small registers (Start, Gap) and one spare line, no storage that scales with memory size.
  • Plain Start-Gap only reaches 53% endurance because it only ever swaps a line with its immediate physical neighbor — address-space randomization (RIB matrix or Feistel network) breaks up spatial clustering and pushes that to 97%, for under 100 bytes total.
  • Write-limited memory creates a new security threat: a targeted write loop can kill one line in under a minute. Region-Based Start-Gap extends that time-to-failure to months or years by partitioning memory into small, independent regions.
  • Result: 10x better lifetime than the baseline with <8 bytes of storage (Start-Gap alone), and 97% of ideal lifetime with <13 bytes (Randomized Start-Gap) — accuracy and near-zero overhead together, not a trade-off.
Six everyday pictures

What Start-Gap feels like

Every analogy below is useful for one part of the intuition and wrong for another — the "where it breaks" line is as important as the picture itself.

A sliding tile (15) puzzle

One empty slot lets everything shuffle

A 15-puzzle has one empty space; sliding tiles into it, over and over, eventually moves every tile through many positions — with no separate map tracking "where each numbered tile currently is." Start-Gap's GapLine is that empty slot, and Gap Movement is the repeated slide.

Where it breaks: a real 15-puzzle lets you slide any adjacent tile in any direction; Start-Gap always shifts in the same fixed direction along a circular buffer — simpler, but far more mechanical than an actual puzzle.
A library card catalog vs. just reshuffling shelves

No index means no lookup — and no upkeep

A card-catalog system (Table-Based Wear Leveling) needs a physical card for every book, filed and re-filed as books move — real storage overhead, and every search means consulting the catalog first. Start-Gap is like a library that simply rotates every book on the shelf by one position on a schedule — no catalog exists, so there's nothing to look up.

Where it breaks: a real library needs to find a specific book by title; Start-Gap only needs to compute where a given logical slot currently lives, which is a much narrower problem than general lookup.
Musical chairs where the same two keep swapping

Neighbor-only swaps don't separate neighbors

If the two most restless kids in musical chairs happen to start out sitting next to each other, and the game only ever swaps neighboring chairs, those two just keep trading places with each other — never actually spreading out. That's plain Start-Gap's shortcoming: it swaps a line only with its immediate physical neighbor.

Where it breaks: real musical chairs has randomness built into who sits where each round; Start-Gap's neighbor swap is completely deterministic, which is exactly why it needs a separate randomization step rather than "just playing more rounds."
Shuffling a deck before dealing

Scatter what was close together

Cards that start out next to each other in a fresh deck end up scattered after a good shuffle. Address-space randomization (a RIB matrix or Feistel network) does the same thing to memory addresses before Start-Gap ever sees them — so lines that were physically close (and likely to be hot together) no longer are.

Where it breaks: a card shuffle is different every hand; Start-Gap's randomizer is static — fixed once at boot or design time and never reshuffled again, since re-randomizing would itself require moving every line.
A ship's watertight compartments

One breach shouldn't sink the whole vessel

A ship divided into separate watertight sections can take on water in one compartment without sinking — the flooding is contained. Region-Based Start-Gap divides memory into independently-managed regions, each with its own Start and Gap, so an attacker hammering one region can't prevent the rest of memory from rotating normally.

Where it breaks: a ship's compartments are static and equal-sized by design; RBSG's region size is a tuned parameter (218 lines in the paper) chosen specifically so a targeted attack can't outrun that region's own Gap Movement — smaller isn't automatically safer against every kind of failure.
A subway turnstile that only lets people through in batches

Slow the attacker down, don't just relocate them

A turnstile that only releases people once a small crowd has gathered behind it slows everyone's throughput a little, but slows a single person trying to rush through repeatedly a lot. The Delayed Write Policy holds writes until the PCM write queue reaches some occupancy, which barely affects normal traffic but forces an attacker's repeated writes to queue up behind others.

Where it breaks: a turnstile delays a specific person; the Delayed Write Policy delays by queue occupancy, not by identifying who's writing — it works precisely because it can't (and doesn't need to) tell attacker traffic from ordinary traffic.
Mechanism, step by step

From a Gap Movement to a security guarantee

Ten steps, from the endurance problem to the two production extensions (randomization and Region-Based Start-Gap).

  1. The endurance problem in one line. A PCM cell endures roughly 107–108 writes. If writes were spread perfectly evenly, a 16GB system would last 4–20 years depending on write traffic — but real programs concentrate writes on a handful of lines, so those lines fail decades early and drag the whole system's usable lifetime down to just 5% of that theoretical maximum.
  2. Why table-based wear leveling doesn't fit main memory. The standard fix tracks a write count per line and remaps hot lines via a separate indirection table — at PCM's 256-byte line granularity, that table needs tens of megabytes to hundreds of megabytes of storage, plus it must be consulted on every single memory access, adding real latency to the critical path.
  3. The key insight: replace the table with algebra. If the physical location of a line is a fixed, directly-computable function of its logical address plus a couple of small registers, no storage that scales with memory size is needed, and there's nothing to look up.
  4. The mechanism: two registers and a spare line. Start-Gap adds one extra memory line (GapLine) to the N lines already in memory, forming a circular buffer of N+1 slots. Two registers, Start and Gap, together encode the entire current mapping from logical to physical addresses.
  5. Gap Movement. Once every ψ writes to memory (the paper uses ψ=100, via one global 7-bit counter incremented on every write), Start-Gap performs a Gap Movement: it copies the contents of the line just before Gap into GapLine, then decrements Gap by one — nudging one line's data into a neighboring physical slot.
  6. Gap Rotation. Once Gap has swept all the way around the circular buffer — one full lap — every line in memory has shifted by exactly one physical position. At that point Start increments by one (modulo N) to record that a complete rotation has happened; for N lines, a Gap Rotation occurs once every (N+1) Gap Movements.
  7. Turning that into a formula. The physical address for logical address LA is computed as PA = (LA + Start) mod N, then incremented by one more if that value is at or past Gap. This is implementable with a handful of logic gates and adds only a few cycles of latency — nothing close to a full table lookup.
  8. The shortcoming: neighbor-only swaps.
    💡
    Because Gap only ever swaps a line with its immediate physical neighbor, a heavily-written line is likely to get swapped with another heavily-written line if hot lines already sit spatially close together — which the paper shows is typical (heavily-written regions cluster, e.g. regions 400–460 for the db1 workload). This caps plain Start-Gap at 53% normalized endurance, still 2x below ideal.
  9. Fixing it with address-space randomization. Running every logical address through a fixed, invertible scrambling function — a Random Invertible Binary (RIB) matrix or a three-stage Feistel network — before Start-Gap manages it breaks up spatial clustering, so physically-close addresses in program order are no longer close together in the space Start-Gap actually rotates. This alone lifts normalized endurance to 97%, for well under 100 bytes of extra storage.
  10. Fixing the security hole: Region-Based Start-Gap (RBSG). A full Gap Rotation across all of memory takes N·ψ writes — for the paper's parameters, far more writes than a single cell can survive, meaning an attacker hammering one address can kill it before Start-Gap ever moves it. RBSG partitions memory into many small, independent regions (each with its own Start and Gap) small enough that a region's own Gap Movement reliably outruns a targeted attack, combined with a Delayed Write Policy that throttles the PCM write queue to slow the attacker further.
Real numbers from the paper

Seven ways to see the difference

Every number below is from the paper's own evaluation (8-core in-order CMP, 16GB PCM main memory, six workloads: oltp, db1, db2, fft, stride, stress — 4 billion memory writes simulated per workload).

1 · Non-uniformity alone costs 20x

For the db2 workload, the maximum write count on any single line was 9,175 versus an average of just 64 writes per line. Across all six workloads, the baseline system (with a strong 64K-spare-line cushion) achieves an average normalized endurance of only 5% — a 20x reduction from the lifetime achievable if writes were spread uniformly.

2 · Start-Gap alone: 10x better, still short of ideal

With ψ=100, Start-Gap lifts average normalized endurance from the baseline's 5% to 53% — a 10x improvement — using less than 8 bytes of total storage overhead and limiting its own extra writes to under 1% of total traffic.

3 · Why 53% isn't 97%: spatial clustering

Dividing the baseline system's memory into 512 regions of 128K lines each and plotting write traffic per region shows that, for the db1 workload, heavily-written regions cluster spatially between regions 400–460. Because plain Start-Gap only swaps a line with its immediate neighbor, it can't spread out writes that are already clustered this closely — capping its endurance well below what full uniformity would achieve.

4 · Randomized Start-Gap: 97%, for under 100 bytes

Adding either a RIB matrix (85 bytes) or a Feistel network (5 bytes) as an address randomizer in front of Start-Gap lifts average normalized endurance to 97% with either scheme — total overhead of 93 bytes (RIB) or 13 bytes (Feistel). For comparison, achieving similar line-granularity accuracy with Table-Based Wear Leveling would require up to 640MB of storage.

5 · Spare lines alone are a weak substitute. Without any spare lines, the baseline achieves under 2% normalized endurance; even after provisioning 6.4 million spare lines (1.6GB of overhead), baseline endurance only reaches 25%. Randomized Start-Gap, by contrast, holds steady around 97% regardless of spare-line count — because it makes all lines wear out at a similar rate instead of relying on replacement capacity.
⚠
6 · The attack, quantified: 32 seconds to kill one line. A malicious loop that writes repeatedly to one PCM line can exhaust its 225-write endurance in about 32 seconds (225 writes × 212 cycles/write ÷ 232 cycles/second), assuming no spare lines. This works against the baseline and against plain or randomized Start-Gap alike — randomization only changes which line dies, since a full Gap Rotation across all of memory takes far more writes than any one cell can survive.

7 · RBSG's defense: minutes to months

Partitioning memory into RBSG regions of 218 lines each (chosen so K < Wmax/ψ) extends the time an attacker needs to cause a failure from under a minute to 4 months at a Delay Write Factor of 1, and up to 64 months (≈1,150 days) at a Delay Write Factor of 16 — while keeping normal-workload normalized endurance at essentially the same ~97% as (non-partitioned) Randomized Start-Gap.

Five questions, misconceptions flagged

Try answering before revealing — each answer names a specific misconception it's checking for.

Medium
Q1. Does randomizing the address space (RIB matrix or Feistel network) stop the targeted write attack described in Section 6?
Show answer
No. Randomization only changes which physical line ends up being hammered — the attacker's writes land on a different line (line B instead of line A), but that line can still be driven to failure in about the same amount of time, since a full Gap Rotation across all of memory still takes far more writes than a single cell can survive.Misconception checked: assuming randomization is a security fix rather than just a wear-leveling improvement.
Medium
Q2. Does Start-Gap need to know which lines are being written heavily in order to work?
Show answer
No — that's the whole point. Start-Gap moves every line on a fixed schedule (every ψ writes) regardless of that line's actual write traffic, so no per-line write-count tracking is needed at all, unlike Table-Based Wear Leveling.Misconception checked: assuming any wear-leveling scheme must track which lines are "hot."
Hard
Q3. Why doesn't Start-Gap alone reach the same ~97% endurance as Randomized Start-Gap?
Show answer
Because Gap Movement always swaps a line with its immediate physical neighbor. If heavily-written lines already sit spatially close together — which the paper's own region-traffic measurements (Figure 9) show is typical — Start-Gap tends to swap one hot line for another nearby hot line rather than for a cold one. Randomization has to scramble the address space first, before Start-Gap's neighbor-only moves can actually help.Misconception checked: assuming Start-Gap's shortfall is a bug rather than a direct, explained consequence of only moving lines to neighboring slots.
Hard
Q4. Does Region-Based Start-Gap (RBSG) push normal-workload endurance higher than plain Randomized Start-Gap?
Show answer
Not really — RBSG's purpose is bounding the time-to-failure under a targeted attack (from under a minute to months or years), not improving normal-workload endurance. For ordinary (non-adversarial) workloads, RBSG's normalized endurance is about the same ~97% as non-partitioned Randomized Start-Gap.Misconception checked: conflating a security extension with a further performance improvement.
Easy
Q5. Do the extra writes caused by Gap Movement itself meaningfully add to PCM wear-out?
Show answer
No — with ψ=100, Gap Movement's own writes add at most 1/(ψ+1), or under 1%, to total write traffic. The paper deliberately chose ψ large enough that wear leveling's own overhead stays a small fraction of the wear it's trying to prevent.Misconception checked: assuming a scheme that moves data around must itself add significant extra wear.
Common questions

FAQ

Q·Where does the name "Start-Gap" come from?▾
It names the algorithm's entire state: the two hardware registers it needs. Start counts how many full rotations all of memory has undergone; Gap tracks the current position of the spare line as it sweeps through memory between rotations.
Q·Is Start-Gap specific to PCM?▾
No — the paper evaluates it on PCM specifically, but notes the technique applies to any lifetime-limited memory technology, including Flash. The only requirement is a hard per-cell write-endurance limit that wear leveling is worth addressing for.
Q·How does this compare to OS-level wear leveling?▾
OS-level approaches still require per-page write-tracking counters and incur a performance slowdown whenever a page is remapped. Start-Gap avoids the per-page storage entirely and performs its remapping in hardware, with only a few cycles of added latency instead of OS-driven page remapping.
Q·Does Start-Gap change the virtual-to-physical mapping the OS sees?▾
No — it's a hardware-only technique operating entirely within the PCM device's own address space, below what the operating system's page table produces. The randomizer and the Start-Gap mapping are both transparent to software.
Q·What's the honest catch?▾
Two things worth flagging. First, the paper's analytical lifetime model relies on an approximation — that a line's new logical address after a rotation is effectively independent of its previous ones — which the authors themselves note isn't rigorously true, though it holds well when Start moves far less often than N. Second, Region-Based Start-Gap doesn't eliminate the security vulnerability, it only buys months-to-years of resistance; a sufficiently patient, sustained attacker (which the paper argues is an unlikely threat model) is still a theoretical concern.
Q·Why three stages specifically for the Feistel network?▾
Prior theoretical work (Luby and Rackoff) showed that three rounds are sufficient to make a Feistel-network cipher behave as a pseudo-random permutation. The paper's own experiments confirmed three stages were sufficient for their address-randomization purposes as well.
